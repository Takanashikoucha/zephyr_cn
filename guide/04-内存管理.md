# 指南 04：内存管理（难度 ★★★）

**主题**：Zephyr 内存子系统导读——堆管理、slab 分配器、内存池、按需分页（demand paging）与关键数据结构。

Zephyr 的内存管理刻意避免"一个大堆打天下"。它把内存划分为三层：**内核对象**（线程、信号量等，静态分配）、**系统堆**（`k_malloc` 背后的 `sys_heap`，动态分配）、**静态内存池**（`k_mem_slab`、`sys_mem_blocks`，无碎片、O(1) 分配）。在支持 MMU 的架构上，还叠加了**按需分页**（demand paging）这一层，让物理内存可以小于虚拟地址空间。理解这三层各自的取舍，是读懂后续所有子系统内存行为的基础。

## 三、核心代码走读

### 3.1 系统堆：`k_malloc` 的三层结构

`k_malloc` 是应用层最常用的动态分配入口。它的实现分三层：**内核同步层**（`kernel/mempool.c`）→ **堆对象层**（`kernel/kheap.c`）→ **底层分配器**（`lib/heap/heap.c`）。

最内层的 `sys_heap` 采用**分桶空闲链表**：按 2 的幂大小分类，每个桶是一条循环链表，分配时先在目标桶做有限次数的精确匹配，失败后用位掩码 `__builtin_ctz` 直接跳到最小的"保证能放下"的桶（`lib/heap/heap.c:382-439`）：

```c
/* lib/heap/heap.c:382 */
static chunkid_t alloc_chunk(struct z_heap *h, chunksz_t sz)
{
	int bi = bucket_idx(h, sz);
	struct z_heap_bucket *b = &h->buckets[bi];

	/* 先在最小桶里做有限次扫描，期望命中尺寸匹配的块 */
	if (b->next != 0U) {
		chunkid_t first = b->next;
		int i = CONFIG_SYS_HEAP_ALLOC_LOOPS;
		do {
			chunkid_t c = b->next;
			if (chunk_size(h, c) >= sz) {
				free_list_remove_bidx(h, c, bi);
				return c;
			}
			b->next = next_free_chunk(h, c);
		} while (--i && b->next != first);
	}

	/* 否则直接取最小非空桶（ctz 定位，O(1)） */
	uint32_t bmask = h->avail_buckets & ~BIT_MASK(bi + 1);
	if (bmask != 0U) {
		int minbucket = __builtin_ctz(bmask);
		chunkid_t c = h->buckets[minbucket].next;
		free_list_remove_bidx(h, c, minbucket);
		return c;
	}
	return 0;
}
```

拿到块后，`sys_heap_alloc()` 会把过大的块**切分**（split）：剩余部分放回空闲链表，避免浪费（`lib/heap/heap.c:458-461`）。整个分配路径不睡眠、O(1) 复杂度，这是它能在 ISR 中使用的根本原因。

`k_heap` 是 `sys_heap` 之上的**可睡眠封装**（`include/zephyr/kernel.h:6310`）：

```c
/* include/zephyr/kernel.h:6310 */
struct k_heap {
	struct sys_heap heap;      /* 底层分配器 */
	_wait_q_t wait_q;          /* 分配失败时挂起的线程 */
	struct k_spinlock lock;    /* 保护 heap 与 wait_q */
};
```

分配失败且允许等待时，线程被挂到 `wait_q`，释放方在 `k_heap_free()` 中唤醒等待者。注意 `kernel/kheap.c:66-87` 的循环结构：每次被唤醒后**重新尝试分配**，直到成功或超时——因为唤醒后内存可能又被别人抢走。

### 3.2 `k_malloc` 与堆引用前缀

`kernel/mempool.c` 里有一个精巧的细节：为了让 `k_free(ptr)` 能找回"这块内存属于哪个堆"，分配时在用户指针**下方**藏了一个 `struct k_heap *` 指针（`kernel/mempool.c:22-56`）：

```c
/* kernel/mempool.c:32 */
	/*
	 * 把 size 加上一个指针大小的空间，
	 * 利用对齐余量（align | sizeof(heap_ref)）
	 * 把堆指针存在对齐边界之下，不浪费任何字节。
	 */
	if (size_add_overflow(size, sizeof(heap_ref), &size)) {
		return NULL;
	}
	__align = align | sizeof(heap_ref);
	...
	heap_ref = mem;
	*heap_ref = heap;
	mem = ++heap_ref;
```

释放时反向操作（`kernel/mempool.c:58-82`）：

```c
/* kernel/mempool.c:58 */
void k_free(void *ptr)
{
	if (ptr != NULL) {
		heap_ref = ptr;
		--heap_ref;              /* 回退到隐藏的堆指针 */
		struct k_heap *heap = *heap_ref;
		k_spinlock_key_t key = k_spin_lock(&heap->lock);
		sys_heap_free(&heap->heap, ptr);
		k_spin_unlock(&heap->lock, key);
	}
}
```

系统堆本身由 CMake 在构建期计算大小（`kernel/CMakeLists.txt:144-177`：汇总所有 `CONFIG_HEAP_MEM_POOL_ADD_SIZE_*` 需求与 `CONFIG_HEAP_MEM_POOL_SIZE` 取最大值），最终以 `K_HEAP_DEFINE(_system_heap, ...)` 静态定义（`kernel/mempool.c:86`）。

### 3.3 内存 slab：无碎片、O(1)

`k_mem_slab` 是固定块大小池，核心技巧是**空闲块自描述**：每个空闲块的内容就是"下一个空闲块的地址"，整条空闲链不需要额外元数据（`kernel/mem_slab.c:111-143`）：

```c
/* kernel/mempool.c 对应逻辑在 kernel/mem_slab.c:133 */
	slab->free_list = NULL;
	p = (char *)(total_size - slab->info.block_size);

	for (uint32_t i = 0; i < slab->info.num_blocks; i++) {
		*(char **)p = slab->free_list;   /* 块内容 = 下一块地址 */
		slab->free_list = p;
		p -= slab->info.block_size;
	}
```

分配与释放因此都是单次指针读写（`kernel/mem_slab.c:220-267`、`kernel/mem_slab.c:269-294`）：

```c
/* kernel/mem_slab.c:227 */
	if (slab->free_list != NULL) {
		/* 取一个空闲块 */
		*mem = slab->free_list;
		slab->free_list = *(char **)(slab->free_list);
		slab->info.num_used++;
		...
	} else if (K_TIMEOUT_EQ(timeout, K_NO_WAIT) ||
		   !IS_ENABLED(CONFIG_MULTITHREADING)) {
		*mem = NULL;
		result = -ENOMEM;
	} else {
		/* 挂起等待，被唤醒后从 _current->base.swap_data 取块 */
		result = z_pend_curr(&slab->lock, key, &slab->wait_q, timeout);
		if (result == 0) {
			*mem = _current->base.swap_data;
		}
	}
```

注意 `swap_data` 的用法：`z_sched_wake()` 把释放的块地址塞进被唤醒线程的 `swap_data`，唤醒后直接取出——省掉了一次加锁后的重新竞争。

slab 的静态定义走**可迭代段**（`include/zephyr/kernel.h:6029-6037`）：`K_MEM_SLAB_DEFINE` 把 slab 对象放进 `k_mem_slab` 段，内核启动时 `init_mem_slab_module()` 用 `STRUCT_SECTION_FOREACH` 统一构建空闲链表（`kernel/mem_slab.c:158-168`）。这套"段 + 遍历"模式是 Zephyr 设备与内核对象初始化的通用机制。

### 3.4 其他分配器

- **`sys_mem_blocks`**（`lib/mem_blocks/mem_blocks.c`）：位图 + 连续块分配，`sys_bitarray_alloc()` 找连续空闲位，适合需要"连续 N 个块"的场景；
- **`sys_multi_heap`**（`lib/heap/multi_heap.c`）：把多个 `sys_heap` 按地址排序后聚合，分配时委托用户提供的 `choice_fn` 决策（先试哪个堆）；
- **`shared_multi_heap`**（`lib/heap/shared_multi_heap.c`）：按 DT 内存属性（`zephyr,memory-attr`）分组的多堆，`smh_choice()` 在同一属性组内逐个尝试（`lib/heap/shared_multi_heap.c:22-48`）；
- **`mem_attr_heap`**（`subsys/mem_mgmt/mem_attr_heap.c`）：从 DT 声明的内存区域动态建堆，用于 MPU 属性不同的内存（如非缓存区）。

### 3.5 按需分页（Demand Paging）

支持 MMU 的架构上，Zephyr 引入第四层：物理页帧可以**换出**到后备存储，缺页时再换入。核心数据结构是每个物理页一个 `struct k_mem_page_frame`（`kernel/include/mmu.h:168-191`）：

```c
/* kernel/include/mmu.h:168 */
struct k_mem_page_frame {
	union {
		/* 已映射：状态位 + 映射到的虚拟地址 */
		uintptr_t va_and_flags;
		/* 空闲：空闲链表节点 */
		sys_sfnode_t node;
	};
};
```

状态位包括 `K_MEM_PAGE_FRAME_FREE/PINNED/RESERVED/MAPPED/BUSY/BACKED`（`kernel/include/mmu.h:140-150`）。`kernel/mmu.c` 维护全局页帧数据库 `k_mem_page_frames[K_MEM_NUM_PAGE_FRAMES]`（`kernel/mmu.c:47`），启动时把未被映射/保留/固定的页全部挂入空闲链表（`kernel/mmu.c:1363-1371`）。

缺页处理在 `do_page_fault()`（`kernel/mmu.c:1832` 起）：先查页是否已换入，未换入则从空闲链表取页帧；**没有空闲页时调用 `do_eviction_select()` 选一个页换出**（`kernel/mmu.c:1928-1945`），随后 `page_frame_prepare_locked()` 把旧页写回后备存储、把新页从后备存储读入。

回收算法可插拔，通过 `include/zephyr/kernel/mm/demand_paging.h` 的三个回调接入（`include/zephyr/kernel/mm/demand_paging.h:235-286`）：

```c
/* include/zephyr/kernel/mm/demand_paging.h:235 */
void k_mem_paging_eviction_add(struct k_mem_page_frame *pf);     /* 加入候选 */
void k_mem_paging_eviction_remove(struct k_mem_page_frame *pf);  /* 移出候选 */
void k_mem_paging_eviction_accessed(uintptr_t phys);             /* 访问标记 */
```

两个内置实现：

- **LRU**（`subsys/mem_mgmt/demand_paging/eviction/lru.c`）：双端队列，被访问的页移到队尾，回收时取队头。实现上不用指针而用**页帧索引数组**（`struct lru_pf_idx`，`lru.c:48-50`），因为每页只存"前后页索引"比存两个指针更省空间；
- **NRU**（`subsys/mem_mgmt/demand_paging/eviction/nru.c`）：按"已访问 × 脏"四象限打分，周期性定时器清除 accessed 位，优先回收"未访问且干净"的页。

后备存储同样可插拔（`k_mem_paging_backing_store_location_get/page_in/page_out` 等回调），内置 RAM 版（`backing_store/ram.c`，演示用）与 QEMU semihosting 版（`backing_store_ondemand_semihost.c`）。

## 五、扩展阅读建议

1. **`lib/heap/heap.h` 全文**：分桶布局、chunk 头字段（LEFT_SIZE / SIZE_AND_USED / FREE_PREV / FREE_NEXT）的注释非常详尽，是理解 `heap.c` 的前提；
2. **`lib/heap/heap_constants.c`**：构建期如何迭代求解桶数量与元数据尺寸（`zephyr_constants_library` 机制），理解"堆声明 N 字节但实际容量小于 N"的原因；
3. **`kernel/mmu.c` 的 `do_page_fault()` 全函数**（约 200 行）：SMP 下的锁策略、`CONFIG_DEMAND_PAGING_ALLOW_IRQ` 的中断窗口处理；
4. **`subsys/mem_mgmt/demand_paging/eviction/lru.c` 头部注释**：LRU 的"理论操作"描述（Theory of Operation）值得逐句读；
5. **Kconfig 选项**：`CONFIG_SYS_HEAP_VALIDATE`/`STRESS`/`INFO`（`lib/heap/Kconfig`）——调试堆时先开这些；`CONFIG_MEM_SLAB_POINTER_VALIDATE`（`kernel/Kconfig:636`）在 `k_mem_slab_free` 中做指针合法性检查；
6. **`kernel/dynamic.c`**：动态线程栈池（`k_thread_stack_alloc`），与 `dynamic_disabled.c` 对照阅读，理解"编译期开关 + 运行时池"的组合；
7. **文档**：`doc/memory/` 下的 heap 与 demand paging 章节，以及 `doc/releases/` 中关于 heap 硬化（hardening level）的说明。
