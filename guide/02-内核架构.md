# 指南 02：`kernel/` 目录导读（内核架构）

**难度：★★**
**主题：内核目录结构、核心模块（线程/任务、调度、同步、内存）、关键头文件**

Zephyr 内核的设计哲学可以概括为一句话：**极小的核心 + 可插拔的机制 + 配置驱动的形态**。核心只包含"线程 + 调度 + 同步原语 + 超时"四件事，其余一切（内存、工作队列、截止时间、用户态）都是围绕这四件事搭起来的机制，且几乎每个机制都有 Kconfig 开关。本篇带你把 `kernel/` 目录拆成模块，并逐个讲清它们的职责边界与协作方式。

---

## 一、目录结构说明

### 1.1 按职责分层的四个圈

```
            ┌─────────────────────────────────────┐
            │  第 4 圈：扩展层（可整体裁剪）          │
            │  smp/  userspace/  paging/          │
            ├─────────────────────────────────────┤
            │  第 3 圈：机制层（Kconfig 驱动）       │
            │  work.c  deadline.c  timeslicing.c  │
            │  system_work_q.c  poll.c  events.c  │
            ├─────────────────────────────────────┤
            │  第 2 圈：同步原语层                  │
            │  sem.c  mutex.c  msg_q.c  mailbox.c │
            │  pipe.c  kheap.c  mempool.c  slab   │
            ├─────────────────────────────────────┤
            │  第 1 圈：核心（几乎不可裁剪）          │
            │  thread.c  sched.c  idle.c          │
            │  timeout.c  init.c  fatal.c         │
            └─────────────────────────────────────┘
```

**第 1 圈（核心）**：线程与调度是 Zephyr 的不可裁剪部分（除非 `CONFIG_MULTITHREADING=n` 退化为单线程模式）。`init.c` 负责内核启动序列，`fatal.c` 处理不可恢复异常，`timeout.c` 是超时机制的公共层。

**第 2 圈（同步原语）**：每个原语都是"等待队列 + 超时"的组合。例如 `sem.c` 的信号量就是"计数 + 一个 `_wait_q_t`"，阻塞时调 `z_pend_curr()`，唤醒时调 `z_unpend1_no_timeout()`——**所有同步原语最终都收敛到调度器的同一组接口**，这是 Zephyr 内核最优雅的架构特征。

**第 3 圈（机制层）**：工作队列（`work.c`）把"回调"变成"线程"；截止时间调度（`deadline.c`）把 EDF 挂到优先级空间上；时间片（`timeslicing.c`）在协程优先级间轮转。

**第 4 圈（扩展层）**：`smp/`（多核 IPI 与 CPU 掩码）、`userspace/`（特权分离、futex、内存域）、`paging/`（按需分页统计）。

### 1.2 `kernel/include/` 内部头文件全景

这是本篇的重点。18 个头文件按职责分组：

| 组 | 头文件 | 职责 |
|---|---|---|
| **调度** | `ksched.h`（316 行） | 调度器内部接口：pend/unpend/wake/yield/优先级比较 |
| | `priority_q.h`（404 行） | 三种就绪/等待队列实现（全 inline） |
| | `run_q.h`（108 行） | 就绪队列操作封装（`queue_thread`/`dequeue_thread`） |
| | `scheduler.h`（147 行） | SMP 调度接口 |
| **线程** | `kthread.h`（282 行） | 线程状态位操作、可抢占性判断 |
| **上下文切换** | `kswap.h` | `z_swap()` 家族声明 |
| **同步** | `kspinlock.h` | 自旋锁实现 |
| **超时** | `timeout_q.h` | 超时后端选择（min-heap/skiplist/wheel/bucket） |
| **架构接口** | `kernel_arch_interface.h` | 架构必须实现的回调 |
| | `kernel_internal.h` | 内核内部公共定义（锁宏、断言） |

**阅读顺序建议**：`kernel_internal.h` → `kthread.h` → `ksched.h` → `priority_q.h` → `run_q.h`。这条链正好是"状态 → 接口 → 数据结构 → 操作封装"的认知顺序。

### 1.3 公共 API 与内部接口的分界

- **公共 API**：`include/zephyr/kernel.h`（7348 行）+ `include/zephyr/kernel/thread.h`（416 行）等，`k_` 前缀，带 Doxygen 承诺；
- **内部接口**：`kernel/include/` 全部，`z_` 前缀，无稳定性承诺；
- **连接点**：`z_impl_` / `z_vrfy_` 前缀 + `__syscall` 宏。

这个分界不是物理隔离而是**命名约定**：同一个功能（如挂起线程）在 `kernel.h` 里是 `k_thread_suspend()`，在 `thread.c` 里是 `z_impl_k_thread_suspend()`（`kernel/thread.c:1685`），中间由 `zephyr/syscalls/k_thread_suspend_mrsh.c` 生成的胶水代码连接。

## 三、核心模块走读

### 3.1 线程模型：一个状态位掩码统治一切

Zephyr 线程没有显式的状态机，而是用**一个 8 位掩码**表达状态（`include/zephyr/kernel_structs.h:55-77`）：

```c
/* include/zephyr/kernel_structs.h:55 */
/* Not a real thread */
#define _THREAD_DUMMY (BIT(0))
/* Thread is waiting on an object */
#define _THREAD_PENDING (BIT(1))
/* Thread is sleeping */
#define _THREAD_SLEEPING (BIT(2))
/* Thread has terminated */
#define _THREAD_DEAD (BIT(3))
/* Thread is suspended */
#define _THREAD_SUSPENDED (BIT(4))
/* Thread is in the process of aborting */
#define _THREAD_ABORTING (BIT(5))
/* Thread is in the process of suspending */
#define _THREAD_SUSPENDING (BIT(6))
/* Thread is present in the ready queue */
#define _THREAD_QUEUED (BIT(7))
```

注意最后两个位：`_THREAD_QUEUED` 表示"线程在就绪队列里"，而 `_THREAD_ABORTING`/`_THREAD_SUSPENDING` 是**过渡态**——abort/suspend 是异步操作（目标线程可能正跑在别的 CPU 上），这两个位标记"正在被 halt"，其他 CPU 会自旋等待它们清零（见 `kernel/sched.c:49-55` 的 `clear_halting()`，SMP 下还带内存屏障）。

"线程是否就绪"不是查一个状态，而是**排除法**（`kernel/include/kthread.h:118-134`）：

```c
/* kernel/include/kthread.h:118 */
static inline bool z_is_thread_prevented_from_running(const struct k_thread *thread)
{
	uint8_t state = thread->base.thread_state;

	return (state & (_THREAD_PENDING | _THREAD_SLEEPING | _THREAD_DEAD |
			 _THREAD_DUMMY | _THREAD_SUSPENDED)) != 0U;
}

static inline bool z_is_thread_ready(const struct k_thread *thread)
{
	return !z_is_thread_prevented_from_running(thread);
}
```

即：只要不在"挂起/睡眠/死亡/假线程"中，就是就绪。这个设计让状态转换代码极简——挂起只需置一个位，无需查表转移。

### 3.2 优先级空间：正数抢占，负数协作

`_thread_base` 里有个精妙的 union（`include/zephyr/kernel/thread.h:76-87`）：

```c
/* include/zephyr/kernel/thread.h:76 */
union {
	struct {
		int8_t prio;        /* 有符号：正=抢占，负=协作 */
		uint8_t sched_locked; /* 调度器锁计数 */
	};
	uint16_t preempt;          /* 拼接后的无符号值 */
};
```

`prio` 是 `int8_t`：正值是抢占优先级（0 最高），负值是协作优先级；`sched_locked` 是 0-0x7F 范围内表示调度器被锁。两者拼成 `preempt` 后，**"不可抢占"等价于 `preempt >= 0x80`**（`kernel/include/kthread.h:66-70` 的 `thread_is_preemptible()`）。一个 uint16_t 同时编码了"优先级类别"和"调度器锁状态"，这是 Zephyr 内核最典型的位技巧。

优先级比较函数在 `kernel/include/ksched.h:170-198`，全部是单指令比较：

```c
/* kernel/include/ksched.h:175 */
static inline bool z_is_prio_higher_or_equal(int prio1, int prio2)
{
	return z_is_prio1_higher_than_or_equal_to_prio2(prio1, prio2);
}

static inline bool z_is_prio1_higher_than_or_equal_to_prio2(int prio1, int prio2)
{
	return prio1 <= prio2;   /* 数值越小优先级越高 */
}
```

若启用 `CONFIG_SCHED_DEADLINE`，同优先级下再比截止时间（`kernel/include/priority_q.h:91-110`）：截止时间越早，有效优先级越高。

### 3.3 就绪队列：三选一的抽象

`_ready_q`（`include/zephyr/kernel_structs.h:130-143`）是一个"按配置变形态"的结构：

```c
/* include/zephyr/kernel_structs.h:130 */
struct _ready_q {
	struct k_thread *cache;   /* 单核：缓存"下一个要跑的线程" */
#if defined(CONFIG_SCHED_SIMPLE)
	sys_dlist_t runq;        /* 实现 1：有序双向链表 */
#elif defined(CONFIG_SCHED_SCALABLE)
	struct _priq_rb runq;    /* 实现 2：红黑树 */
#elif defined(CONFIG_SCHED_MULTIQ)
	struct _priq_mq runq;    /* 实现 3：每优先级一条链 + 位图 */
#endif
};
```

三种实现的取舍（`kernel/Kconfig:271-321` 的 help 文本）：

| 实现 | 复杂度 | 适用场景 |
|---|---|---|
| **SIMPLE**（链表） | 插入 O(N)，代码 ~2KB 省 | 可运行线程 ≤3 个的极简系统 |
| **SCALABLE**（红黑树） | O(logN) | 可运行线程 >20 个 |
| **MULTIQ**（多级队列） | 几乎 O(1) | 经典教科书方案，RAM 换时间；不兼容 deadline |

`kernel/include/priority_q.h:14-46` 用宏把统一接口 `_priq_run_add/remove/best/yield` 映射到具体实现；`_priq_mq` 的核心技巧是**位图加速**（`kernel/include/priority_q.h:291-303`）：每个优先级一个链表头，再用 `unsigned long bitmask[]` 记录哪些优先级非空，`z_priq_mq_best_queue_index()` 用 `u32_count_trailing_zeros` 一条指令找到最高非空优先级。

单核下还有一个 `cache` 优化（`kernel/include/ksched.h:80-88`）：

```c
/* kernel/include/ksched.h:80 */
static ALWAYS_INLINE void *z_sched_next_handle(struct k_thread *curr)
{
#ifndef CONFIG_SMP
	if (curr == _kernel.ready_q.cache) {
		return NULL;   /* 下一个还是自己 → 不切换 */
	}
#endif
	return z_get_next_switch_handle(NULL);
}
```

中断返回路径先查 cache，若下一个线程就是当前线程，直接返回——**省掉整个上下文切换**。这是 Zephyr 中断延迟低的关键之一。

### 3.4 同步原语：等待队列的统一收敛

所有同步原语共享同一个等待队列类型（`include/zephyr/kernel_structs.h:308-328`）：

```c
/* include/zephyr/kernel_structs.h:311 */
typedef struct {
	struct _priq_rb waitq;    /* 或 sys_dlist_t，按 WAITQ_* 配置 */
} _wait_q_t;
```

以信号量为例，其生命周期完全由调度器接口驱动：

1. **阻塞**：`z_pend_curr()`（`kernel/sched.c:522`）——把当前线程移出就绪队列、挂到信号量的 waitq、武装超时、`z_swap_locked()` 切走；
2. **唤醒**：`z_unpend1_no_timeout()`（`kernel/sched.c:555`）——取 waitq 中优先级最高的线程，移出 waitq、重新入队、必要时触发切换。

`kernel/include/ksched.h:293-310` 的 `z_sched_wake()` 是更通用的封装，值得精读：

```c
/* kernel/include/ksched.h:293 */
static ALWAYS_INLINE bool z_sched_wake(_wait_q_t *wait_q,
				       int swap_retval, void *swap_data)
{
	struct k_thread *thread;
	bool ret = false;

	LOCK_SCHED_SPINLOCK {
		thread = z_unpend_first_thread_locked(wait_q);
		if (thread != NULL) {
			z_thread_return_value_set_with_data(thread,
							    swap_retval,
							    swap_data);
			z_sched_ready_locked(thread);
			ret = true;
		}
	}

	return ret;
}
```

注意它的注释（`kernel/include/ksched.h:234-249`）解释了一个 SMP 竞态：唤醒必须在调度锁内**原子完成**"取最高优先级等待者 → 设置返回值 → 重新就绪"三步，否则另一 CPU 上正在飞的超时处理器可能抢先唤醒线程，导致线程带着过期的 `swap_retval` 醒来。这是读 Zephyr 内核时最能体现"锁粒度设计"的片段。

### 3.5 内存管理：静态优先，堆是例外

Zephyr 的编码规范（MISRA Dir 4.12）禁止动态分配，内核与子系统用 `k_malloc()`/`k_heap`/slab/`net_buf` 池。`kernel/` 下四个内存文件分工：

- `kheap.c`：通用堆（`K_HEAP_DEFINE` 宏定义）；
- `mempool.c`：定长对象池（`K_MEM_POOL_DEFINE`）；
- `mem_slab.c`：slab 分配器；
- `mmu.c` + `paging/`：MMU 与按需分页（`CONFIG_USERSPACE` 下线程可分页）。

线程创建时通过 `k_thread_heap_assign()` 绑定资源池（`kernel/thread.c:1150` 附近的 `z_setup_new_thread()` 末尾 `new_thread->resource_pool = _current->resource_pool`），实现"线程的内存开销归属其创建者"。

### 3.6 超时机制：四种后端

`struct _timeout`（`include/zephyr/kernel_structs.h:334-377`）是另一个"按配置变形态"的结构，支持四种后端：

- **delta-list**（默认）：按距上次超时排序的链表，O(1) 插入、O(N) 最坏扫描；
- **min-heap**：O(logN)；
- **skiplist**：期望 O(logN)，代码更大；
- **wheel**（`timeout_wheel.h`）：定时器轮，O(1) 摊销。

线程的超时直接内嵌在 `_thread_base.timeout`（`include/zephyr/kernel/thread.h:120-123`），线程阻塞时由 `z_add_thread_timeout()` 挂入后端，到期后回调 `z_thread_timeout()`（`kernel/sched.c:502`）唤醒线程。

## 四、模块协作总图

```
 应用代码
    │  k_* API（include/zephyr/kernel.h）
    ▼
┌──────────────────────────────────────────────────┐
│  同步原语层：sem / mutex / msg_q / mailbox / pipe │
│  机制层：work_q / deadline / timeslicing / poll  │
└───────────────┬──────────────────────────────────┘
                │  z_pend_curr / z_unpend1 / z_sched_wake
                ▼
┌──────────────────────────────────────────────────┐
│  调度核心：sched.c（next_up / update_cache）      │
│  线程管理：thread.c（create / halt / join）      │
│  队列：priority_q.h（simple / rb / mq）          │
└───────────────┬──────────────────────────────────┘
                │  z_swap / arch_switch
                ▼
┌──────────────────────────────────────────────────┐
│  架构层：arch/<arch>/（swap 汇编、时钟、中断）      │
└──────────────────────────────────────────────────┘
```

三条主线：

1. **控制流向下**：API → 原语 → 调度器 → 架构切换；
2. **事件流向上**：超时到期 / 中断到达 → 唤醒 → 调度器重选线程；
3. **状态横向**：所有模块只通过 `_thread_base.thread_state` 位掩码与优先级通信，无隐藏状态。

## 五、扩展阅读建议

1. **`kernel/sem.c` 全文**（约 200 行）：最短的同步原语，把"waitq + timeout + 调度器接口"三件套用一遍；
2. **`kernel/work.c` + `kernel/system_work_q.c`**：理解"回调变线程"的机制，以及系统工作队列如何复用空闲线程；
3. **`kernel/timeout.c` + 四种 `timeout_*.h`**：对比四种后端的数据结构，理解"同一接口、四种实现"的 Kconfig 驱动设计；
4. **`kernel/smp/`**（若你对多核感兴趣）：`ipi.c` 的核间调度通知机制；
5. **`doc/kernel/`**：官方内核文档，`doc/kernel/services/`（同步原语）、`doc/kernel/memory_management/`、`doc/kernel/timing_functions/` 与源码一一对应；
6. **`tests/kernel/`**：每个特性都有测试，`tests/kernel/threads/` 与 `tests/kernel/synchronization/` 是理解"正确行为"的最佳锚点。
