内存保护设计
########################

Zephyr 的内存保护设计针对具有 MPU
（内存保护单元）硬件的
微控制器。
我们
支持
某些
架构，
如
x86，
它们
具有
分页
MMU
（内存
管理
单元），
但
在
那种
情况
下
MMU
像
MPU
一样
使用
恒等
页
表。

下面
所有
讨论
都
将
使用
MPU
术语；
具有
MMU
的
系统
可以
被认为
具有
无
限制
数量
可编程
区域
的
MPU。

当
启用
Zephyr
内存
保护
特性
时，
内存
访问
配置
有
几个
不同
的
级别，
我们
将
在此
描述：

启动
时
内存
配置
******************************

这是
内核
启动
后
MPU
的
配置。
它
应该
包含
以下
内容：

- 任何
  需要
  特殊
  缓存
  或
  写回
  策略
  以
  进行
  基本
  硬件
  和
  驱动
  功能
  的
  内存
  区域
  配置。
  注意
  大多数
  MPU
  具有
  默认
  内存
  访问
  策略
  映射
  的
  概念，
  可以
  启用
  为
  没有
  MPU
  区域
  配置
  的
  任何
  内存
  区域
  的
  "背景"
  映射。
  强烈
  建议
  使用
  此
  功能
  以
  最大化
  最终
  用户
  可用
  的
  MPU
  区域
  数量。
  在
  ARMv7-M/ARMv8-M
  上
  这
  称为
  系统
  地址
  映射，
  其他
  CPU
  可能
  具有
  类似
  能力。
  有关
  如何
  在
  设备
  树
  中
  注释
  系统
  映射
  的
  信息
  请参阅
  :ref:`mem_mgmt_api`。

- 可
  执行
  的
  只读
  区域
  或
  区域，
  用于
  程序
  文本
  和
  ro-data，
  用户
  模式
  可
  访问。
  这
  可以
  进一步
  细分
  为
  ro-data
  的
  只读
  区域
  和
  文本
  的
  只读
  可
  执行
  区域，
  但
  这
  将
  需要
  额外
  的
  MPU
  区域。
  这是
  必需
  的，
  以便
  以
  用户
  模式
  运行
  的
  线程
  可以
  读取
  ro-data
  并
  取
  指令。

- 根据
  配置，
  支持
  额外
  特性
  （如
  GCOV、
  HEP
  等）
  的
  用户
  可
  访问
  读写
  区域。

假设
存在
允许
监督
模式
访问
其
需要
的
任何
内存
的
背景
映射，
且
定义了
授予
用户
模式
访问
文本/ro-data
的
区域，
这
就
足够
作为
启动
时
配置。

硬件
栈
溢出
***********************

:kconfig:option:`CONFIG_HW_STACK_PROTECTION`
是
一个
可选
特性，
在
系统
以
监督
模式
运行
时
检测
栈
缓冲区
溢出。
这
捕获
整个
栈
缓冲区
溢出
的
问题，
而
不
是
单个
栈
帧，
用于
此
请
使用
编译器
辅助
的
:kconfig:option:`CONFIG_STACK_CANARIES`。

与
任何
监督
模式
崩溃
一样，
在
监督
模式
栈
溢出
后
无法
对
系统
的
整体
健康状况
做出
任何
保证，
任何
此类
实例
应
被视为
严重
错误。
但是
了解
这些
溢出
何时
发生
仍然
非常
有用，
因为
没有
健壮
的
检测
逻辑，
栈
缓冲区
溢出
时
系统
要么
以
神秘
方式
崩溃，
要么
以
未定义
方式
运行。

某些
系统
通过
在
运行时
创建
一个
"保护"
MPU
区域
来
实现
此
特性，
该
区域
设置
为
只读，
位于
监督
模式
栈
缓冲区
的
开头
或
紧接
其
之前。
如果
栈
溢出
将
生成
异常。

此
特性
是
可选
的，
检测
用户
模式
栈
溢出
不
需要
它；
禁用
此
特性
可能
释放
1-2
个
MPU
区域，
具体
取决于
MPU
设计。

其他
系统
可能
具有
专门
的
CPU
支持
来
捕获
栈
溢出，
不
需要
额外
的
MPU
区域。

线程
栈
************

任何
以
用户
模式
运行
的
线程
都
需要
访问
其
自身
的
栈
缓冲区。
在
上下文
切换
到
用户
模式
线程
时，
专用
MPU
区域
或
MMU
页
表
条目
用于
配置
线程
栈
的
访问
权限。

线程
栈
的
访问
策略
通常
如下：

- 线程
  对
  其
  自身
  栈
  缓冲区
  具有
  读写
  访问
  权限。
- 线程
  默认
  对
  不
  属于
  同一
  内存
  域
  的
  其他
  用户
  线程
  栈
  没有
  访问
  权限。
- 线程
  对
  监督
  线程
  拥有
  的
  线程
  栈
  或
  用于
  处理
  系统
  调用
  提权、
  中断
  或
  CPU
  异常
  的
  线程
  栈
  没有
  访问
  权限。

内存
域
************

内存
域
是
一组
线程
栈
的
集合，
其中
的
线程
可以
相互
访问
栈
缓冲区。
内存
域
的
概念
允许
应用
将
线程
分组
为
逻辑
"应用"，
每个
应用
具有
自己
的
线程
组
和
私有
数据
结构。

线程
可以
在
创建
时
分配
到
内存
域，
使用
线程
选项
:c:macro:`K_INHERIT_PERMS`
或
通过
系统
调用
API
在
运行时
分配。

每个
内存
域
需要
以下
配置：

- 域
  中
  线程
  栈
  的
  访问
  属性
  列表。
- 域
  的
  名称
  （可选，
  用于
  调试）。

内存
分区
************

内存
分区
是
内存
域
的
子集，
其中
的
线程
栈
具有
相同
的
访问
属性。
内存
分区
用于
最小化
需要
编程
的
MPU
区域
数量。

分区
属性
指定
监督
模式
和
用户
模式
对
分区
的
访问
权限。
特定
架构
的
可用
分区
属性
列表
在
架构
特定
的
include
文件
``include/zephyr/arch/<arch name>/arch.h``
中
（例如，
:zephyr_file:`include/zephyr/arch/arm/arch.h`。
）。
分区
属性
的
一些
示例：

.. code-block:: c

    /* Denote partition is privileged read/write, unprivileged read/write */
    K_MEM_PARTITION_P_RW_U_RW
    /* Denote partition is privileged read/write, unprivileged read-only */
    K_MEM_PARTITION_P_RW_U_RO

在
几乎
所有
情况
下
``K_MEM_PARTITION_P_RW_U_RW``
是
正确
的
选择。

选项

配置
