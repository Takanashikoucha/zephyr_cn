MPU 栈对象
#################

线程栈创建
*********************

线程栈使用 :c:macro:`K_THREAD_STACK_DEFINE()`
静态声明。

对于
使用
内存
保护
单元
（MPU）
硬件
的
架构，
栈
是
物理
连续
的
分配。
此
连续
分配
对
栈
在
内存
中
的
放置
以及
其他
特性
（如
栈
保护
和
用户
空间）
的
实现
有
影响。
放置
的
影响
直接
归因于
MPU
区域
的
对齐
要求。
这
在
下面
的
内存
放置
部分
讨论。

栈保护
************

栈
保护
机制
需要
能够
限制
内存
访问
的
硬件
支持。
内存
保护
单元
可以
提供
这种
支持。
MPU
提供
固定
数量
的
区域。
每个
区域
包含
关于
该
特定
区域
的
起始、
结束、
大小
和
要
强制
执行
的
访问
属性
的
信息。

栈
保护
通过
使用
单个
MPU
区域
并
将
该
区域
的
属性
设置
为
不
允许
写
访问
来
实现。
如果
发生
无效
访问，
将
导致
故障。
栈
保护
定义
在
栈
的
底部
（最低
地址）。

内存放置
****************

在
栈
创建
期间，
对
内存
分配
强制
执行
一组
约束。
这些
约束
包括
确定
栈
的
对齐
和
栈
的
正确
尺寸。
在
二进制
链接
期间，
这些
约束
用于
正确
放置
栈。

内存
约束
的
主要
来源
是
SoC
的
MPU
设计。
MPU
设计
可能
对
区域
定义
有
特定
约束。
这些
可以
包括
起始
和
结束
地址
的
对齐、
分配
的
大小，
甚至
重叠
区域
之间
的
交互。

某些
MPU
要求
每个
区域
按
2
的
幂
对齐。
这些
SoC
将
定义
:kconfig:option:`CONFIG_MPU_REQUIRES_POWER_OF_TWO_ALIGNMENT`。
这意味着
1500
字节
的
栈
应该
对齐
到
2kB
边界，
且
栈
大小
也
应该
调整
为
2kB
以
确保
没有
其他
东西
放置
在
区域
的
剩余
部分。
包含
未
修改
的
ARM
v7m
MPU
的
SoC
将
有
这些
约束。

某些
ARM
MPU
使用
起始
和
结束
地址
定义
MPU
区域，
且
起始
和
结束
地址
都
需要
32
字节
对齐。
这种
MPU
的
示例
在
NXP
FRDM
K64F
中
找到。

MPU
可能
具有
区域
优先级
机制，
使用
覆盖
内存
访问
的
最高
优先级
区域
来
确定
强制
策略。
其他
可能
逻辑
或
区域
来
确定
强制
策略。

大小
和
对齐
约束
可能
导致
栈
分配
大于
请求
的
大小。
区域
优先级
机制
可能
导致
实现
栈
保护
时
增加
某些
复杂性。
