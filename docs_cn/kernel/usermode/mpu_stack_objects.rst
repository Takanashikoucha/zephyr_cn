MPU 栈对象
#################

线程栈创建
*********************

线程栈用 :c:macro:`K_THREAD_STACK_DEFINE()` 静态声明。

对于利用内存保护单元（MPU）硬件的架构，
栈是物理连续的分配。这种连续分配对栈在内存中的放置有影响，
也对栈保护、用户空间等其他特性的实现有影响。
放置方面的影响直接归因于 MPU 区域的对齐要求。
这在下文的内存放置部分讨论。

栈保护
************

栈保护机制需要能够限制内存访问的硬件支持。
内存保护单元可以提供这种支持。
MPU 提供固定数量的区域。
每个区域包含关于要对该区域强制执行的信息：
起始地址、结束地址、大小和访问属性。

栈保护（stack guard）通过使用单个 MPU 区域实现，
并将该区域的属性设置为不允许写访问。
如果发生非法访问，就会产生故障（fault）。
栈保护定义在栈的底部（最低地址处）。

内存放置
****************

在创建栈的过程中，会对内存分配强制一组约束。
这些约束包括确定栈的对齐和栈的正确大小。
在链接二进制文件时，这些约束被用来正确放置栈。

内存约束的主要来源是 SoC 的 MPU 设计。
MPU 设计可能对区域定义有特定约束。
这些可以包括起始和结束地址的对齐、分配的大小，
甚至是重叠区域之间的交互。

某些 MPU 要求每个区域对齐到 2 的幂。
这些 SoC 会定义 :kconfig:option:`CONFIG_MPU_REQUIRES_POWER_OF_TWO_ALIGNMENT`。
这意味着一个 1500 字节的栈应对齐到 2kB 边界，
且栈大小也应调整为 2kB，以确保该区域的剩余部分不会放置其他东西。
包含未修改的 ARM v7m MPU 的 SoC 会有这些约束。

某些 ARM MPU 使用起始和结束地址来定义 MPU 区域，
且起始和结束地址都需要 32 字节对齐。
这类 MPU 的一个示例可在 NXP FRDM K64F 中找到。

MPU 可能有区域优先级（region priority）机制，
使用覆盖该内存访问的最高优先级区域来确定强制执行的策略。
其他 MPU 可能将区域逻辑或（OR）起来以确定强制执行策略。

大小和对齐约束可能导致栈分配大于请求的大小。
区域优先级机制可能导致实现栈保护时增加一些复杂性。
