概述
########

威胁模型
************

用户
模式
线程
被
Zephyr
视为
不可
信任，
因此
与
其他
用户
模式
线程
和
内核
隔离。
有
缺陷
或
恶意
的
用户
模式
线程
不能
泄露
或
修改
另一个
线程
或
内核
的
私有
数据/资源，
且
不能
干扰
或
控制
另一个
用户
模式
线程
或
内核。

Zephyr
用户
模式
特性
的
示例
用例：

- 内核
  可以
  保护
  系统
  免受
  许多
  非
  故意
  的
  编程
  错误
  的
  影响，
  这些
  错误
  否则
  可能
  静默
  或
  显著
  破坏
  系统。

- 内核
  可以
  对
  复杂
  的
  数据
  解析器
  （如
  解释器、
  网络
  协议
  和
  文件
  系统）
  进行
  沙箱
  隔离，
  使得
  恶意
  的
  第三方
  代码
  或
  数据
  不能
  破坏
  内核
  或
  其他
  线程。

- 内核
  可以
  支持
  多个
  逻辑
  "应用"
  的
  概念，
  每个
  应用
  具有
  自己
  的
  线程
  组
  和
  私有
  数据
  结构，
  如果
  一个
  崩溃
  或
  以
  其他
  方式
  被
  破坏，
  它们
  之间
  相互
  隔离。

设计目标
============

对于
以
非
特权
CPU
状态
运行
的
线程
（以下
称为
"用户
模式"），
我们
旨在
保护
以下
方面：

- 我们
  防止
  访问
  未
  特别
  授予
  的
  内存，
  或
  对
  具有
  不兼容
  策略
  的
  内存
  进行
  错误
  访问，
  例如
  尝试
  写入
  只读
  区域。

  - 对
    线程
    栈
    缓冲区
    的
    访问
    将
    通过
    部分
    依赖
    底层
    内存
    保护
    硬件
    的
    策略
    控制。

    - 用户
      线程
      默认
      对其
      自身
      栈
      缓冲区
      具有
      读写
      访问
      权限。

    - 用户
      线程
      默认
      永远
      对
      不
      属于
      同一
      内存
      域
      的
      用户
      线程
      栈
      没有
      访问
      权限。

    - 用户
      线程
      默认
      永远
      对
      监督
      线程
      拥有
      的
      线程
      栈
      或
      用于
      处理
      系统
      调用
      提权、
      中断
      或
      CPU
      异常
      的
      线程
      栈
      没有
      访问
      权限。

    - 用户
      线程
      根据
      硬件，
      可能
      对
      同一
      内存
      域
      中
      其他
      用户
      线程
      的
      栈
      具有
      读写
      访问
      权限。

      - 在
        MPU
        系统
        上，
        线程
        只能
        访问
        其
        自身
        的
        栈
        缓冲区。

      - 在
        MMU
        系统
        上，
        线程
        可以
        访问
        同一
        内存
        域
        中
        的
        任何
        用户
        线程
        栈。
        可
        移植
        代码
        不
        应
        假设
        此
        行为。

  - 默认
    情况
    下，
    程序
    文本
    和
    只读
    数据
    在
    整个
    内核
    范围
    内
    对
    所有
    线程
    以
    只读
    基础
    可
    访问。
    此
    策略
    可以
    调整。

  - 用户
    线程
    默认
    不
    被
    授予
    除
    上述
    之外
    任何
    内存
    的
    默认
    访问
    权限。

- 我们
  防止
  使用
  未
  特别
  授予
  的
  设备
  驱动程序
  或
  内核
  对象，
  权限
  粒度
  在
  每
  对象
  或
  每
  驱动程序
  实例
  基础
  上。

- 我们
  验证
  具有
  错误
  参数
  的
  内核
  或
  驱动
  API
  调用，
  这些
  调用
  否则
  将
  导致
  崩溃
  或
  破坏
  内核
  私有
  的
  数据
  结构。
  这
  包括：

  - 使用
    错误
    的
    内核
    对象
    类型。

  - 使用
    超出
    适当
    范围
    或
    具有
    无
    意义
    值
    的
    参数。

  - 传递
    调用
    线程
    没有
    足够
    读
    或
    写
    访问
    权限
    的
    内存
    缓冲区，
    具体
    取决于
    API
    的
    语义。

  - 使用
    不
    处于
    适当
    初始化
    状态
    的
    内核
    对象。

- 我们
  确保
  检测
  和
  安全
  处理
  用户
  模式
  栈
  溢出。

- 我们
  防止
  调用
  被
  内核
  配置
  排除
  的
  函数
  的
  系统
  调用。

- 我们
  防止
  禁用
  或
  篡改
  内核
  定义
  和
  硬件
  强制
  的
  内存
  保护。

- 我们
  防止
  除
  通过
  内核
  定义
  的
  系统
  调用
  和
  中断
  处理
  程序
  外
  从
  用户
  到
  监督
  模式
  的
  重新
  进入。

- 我们
  防止
  引入
  新
  的
  可
  执行
  代码
  到
  监督
  模式
  可
  访问
  的
  内存
  中。

- 我们
  防止
  用户
  线程
  修改
  内核
  或
  驱动
  的
  代码
  或
  数据
  结构，
  除非
  通过
  明确
  授予
  的
  系统
  调用
  接口。

约束
====

用户
模式
的
实现
存在
某些
约束：

- 内核
  对象、
  线程
  栈
  和
  设备
  驱动程序
  实例
  必须
  在
  构建
  时
  定义
  才能
  从
  用户
  模式
  使用。
  内核
  对象
  的
  动态
  用例
  需要
  通过
  预
  定义
  的
  可用
  对象
  池
  进行。

如果
在
内核
启动
后
加载
额外
的
应用
二进制
数据
用于
执行，
存在
某些
约束：

- 加载
  的
  对象
  代码
  将
  无法
  定义
  任何
  内核
  能
  识别
  的
  内核
  对象。
  此
  代码
  将
  需要
  使用
  从
  池
  请求
  内核
  对象
  的
  API。

- 类似
  地，
  由于
  加载
  的
  对象
  代码
  不
  是
  内核
  构建
  过程
  的
  一部分，
  此
  代码
  将
  无法
  安装
  中断
  处理
  程序、
  实例化
  设备
  驱动程序
  或
  定义
  系统
  调用，
  无论
  其
  以
  什么
  模式
  运行。

- 不
  来自
  已
  验证
  来源
  的
  加载
  对象
  代码
  应该
  始终
  在
  CPU
  已经
  处于
  用户
  模式
  时
  进入。
