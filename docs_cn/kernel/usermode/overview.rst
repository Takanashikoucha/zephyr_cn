概览
########

威胁模型
************

Zephyr 将用户模式线程视为不可信的，
因此它们与其他用户模式线程以及内核相互隔离。
一个有缺陷或恶意的用户模式线程
不能泄漏或修改另一个线程或内核的私有数据/资源，
也不能干扰或控制另一个用户模式线程或内核。

Zephyr 用户模式特性的示例用例：

- 内核可以防止许多意外的编程错误，
  这些错误否则可能静默地或灾难性地破坏系统。

- 内核可以沙箱化（sandbox）复杂的数据解析器
  （例如解释器、网络协议和文件系统），
  使恶意的第三方代码或数据无法破坏内核或其他线程。

- 内核可以支持多个逻辑"应用程序"的概念，
  每个应用程序有自己的线程组和私有数据结构；
  如果其中一个崩溃或以其他方式被破坏，它们之间相互隔离。

设计目标
============

对于运行在非特权 CPU 状态（以下称为"用户模式"）的线程，
我们旨在防御以下威胁：

- 我们阻止访问未被明确授予的内存，
  或错误地访问策略不兼容的内存（例如尝试写入只读区域）。

  - 对线程栈缓冲区的访问将由一项策略控制，
    该策略部分取决于底层的内存保护硬件。

    - 用户线程默认对自己的栈缓冲区具有读写访问权限。

    - 用户线程默认从不访问不属于同一内存域成员的用户线程栈。

    - 用户线程默认从不访问由超级用户线程拥有的线程栈，
      或用于处理系统调用权限提升、中断或 CPU 异常的线程栈。

    - 根据硬件情况，用户线程可能对同一内存域中
      其他用户线程的栈具有读写访问权限。

      - 在 MPU 系统上，线程只能访问自己的栈缓冲区。

      - 在 MMU 系统上，线程可以访问同一内存域中任何用户线程的栈。
        可移植代码不应假设这一点。

  - 默认情况下，程序文本和只读数据在整个内核范围内
    以只读方式对所有线程可访问。该策略可以调整。

  - 用户线程默认除了上述之外，不被授予对任何内存的访问权限。

- 我们阻止使用未被明确授予的设备驱动或内核对象，
  权限粒度在单个对象或单个驱动实例的基础上。

- 我们验证参数错误的内核或驱动 API 调用，
  这些调用否则会导致崩溃或破坏内核私有的数据结构。这包括：

  - 使用错误的内核对象类型。

  - 使用超出合理范围或无意义的参数值。

  - 传递调用线程根据 API 语义
    没有足够读或写权限的内存缓冲区。

  - 使用未处于正确初始化状态的内核对象。

- 我们确保检测用户模式栈溢出并安全地处理它。

- 我们阻止调用被内核配置排除的函数的系统调用。

- 我们阻止禁用或篡改内核定义的、由硬件强制执行的内存保护。

- 除了通过内核定义的系统调用和中断处理程序之外，
  我们阻止从用户模式重新进入超级用户模式。

- 我们阻止用户模式线程引入新的可执行代码，
  除非内核系统调用在支持范围内允许这样做。

我们明确不防御以下攻击：

- 内核本身以及任何运行在超级用户模式的线程都被视为可信的。

- 工具链以及构建系统使用的任何辅助程序都被视为可信的。

- 内核构建被视为可信的。创建有效内核对象表、
  定义系统调用和配置中断有大量构建时逻辑。
  此过程中操作的所有 .elf 二进制文件都被视为可信代码。

- 我们无法防止在内核模式中进行的内存域配置错误
  向用户线程暴露内核私有数据结构。
  内核对象的 RAM 应始终配置为仅超级用户可访问。

- 可以创建用户模式线程的顶层声明，
  并分配它们对内核对象的权限。
  一般而言，产生 zephyr.elf 的内核构建中的
  所有 C 文件和头文件都被视为可信的。

- 我们不防御通过线程 CPU 饥饿（starvation）发起的拒绝服务攻击。
  Zephyr 没有线程优先级老化（priority aging），
  特定优先级的用户线程可以饿死所有较低优先级的线程；
  如果未启用时间片（time-slicing），还会饿死相同优先级的其他线程。

- 对同时可以活动多少线程有构建时定义的上限，
  超过该上限后创建新的用户线程将失败。

- 运行在超级用户模式的线程的栈溢出可能被捕获，
  但无法保证系统的完整性。

高层策略细节
*************************

从宏观上讲，我们通过以下机制实现这些线程级的内存保护目标：

- 任何用户线程只能访问内存的一个子集：通常是其栈、程序文本、
  只读数据，以及所属 :ref:`memory_domain` 中配置的任何分区。
  对任何其他 RAM 的访问必须通过系统调用代表该线程完成，
  或由超级用户线程使用内存域 API 明确授予。
  新创建的线程继承父线程的内存域配置。
  线程可以通过共享同一内存域的成员资格，
  或通过信号量和管道等内核对象相互通信。

- 用户线程不能直接访问属于内核对象的内存。
  虽然使用指向内核对象的指针来引用它们，
  但对内核对象的实际操作是通过系统调用接口完成的。
  设备驱动和线程栈也被视为内核对象。
  这确保了内核对象内部任何内核私有的数据都不会被篡改。

- 用户线程默认除了自己的线程对象外，
  对任何内核对象或驱动都没有访问权限。
  此类访问必须由另一个线程授予，该线程要么运行在超级用户模式，
  要么对接收线程的对象和被授予访问的内核对象都持有权限。
  创建新线程时有一个选项，可自动继承授予父线程的
  所有内核对象的权限（父线程本身除外）。

- 出于性能和占用空间（footprint）的考虑，
  Zephyr 通常对内核对象或设备驱动 API 做很少或不做参数错误检查。
  从用户模式通过系统调用的访问涉及额外一层处理函数，
  预期它们严格验证访问权限和对象类型，
  通过边界检查或其他手段检查其他参数的有效性，
  并验证所涉及的任何内存缓冲区的正确读写访问。

- 线程栈的定义方式使得超出指定的栈空间会产生硬件故障。
  具体做法因架构而异。

约束
***********

所有内核对象、线程栈和设备驱动实例，
如果要被用户模式使用，必须在构建时定义。
内核对象的动态用例需要通过预定义的可用对象池。

如果在内核启动后加载额外的应用程序二进制数据来执行，
存在一些约束：

- 加载的对象代码无法定义任何会被内核识别的内核对象。
  该代码改为需要使用从池中请求内核对象的 API。

- 类似地，由于加载的对象代码不是内核构建过程的一部分，
  无论它运行在什么模式，都无法安装中断处理程序、
  实例化设备驱动或定义系统调用。

- 不来自已验证来源的加载对象代码，
  应始终在 CPU 已处于用户模式的状态下进入。
