内核对象
##############

内核对象可以是三类数据之一：

* 核心内核对象，如信号量、线程、管道等。
* 线程栈，它是 :c:struct:`z_thread_stack_element`
  的数组，使用 :c:macro:`K_THREAD_STACK_DEFINE()`
  声明
* 属于已定义子系统集合之一的
  设备驱动程序实例（const struct device）

已知内核对象和驱动程序子系统的集合
在
:zephyr_file:`include/zephyr/sys/kobject.h`
中
定义为
:c:enum:`k_objects`。

内核对象对用户线程完全是不透明的。用户线程
在
进行
API
调用
时
使用
内核
对象
的
地址，
但
永远
不得
解引用
这些
地址，
这样做
将
导致
内存
保护
故障。
所有
内核
对象
必须
放置
在
用户
线程
无法
访问
的
内存
中。

由于
用户
线程
不得
直接
操作
内核
对象，
所有
对
它们
的
使用
必须
通过
系统
调用
进行。
为了
对
内核
对象
执行
系统
调用，
系统
调用
处理
函数
会
执行
检查，
确认
内核
对象
地址
有效
且
调用
线程
具有
足够
的
权限
来
操作
它。

对
对象
的
权限
还
具有
对
对象
的
引用
的
语义。
这
对
某些
执行
临时
分配
的
对象
API
，
或
其
本身
从
运行时
内存
池
分配
的
对象
很
重要。

如果
对象
失去
所有
引用，
可能
发生
两个
事件：

* 如果
  对象
  有
  关联
  的
  清理
  函数，
  可能
  调用
  清理
  函数
  释放
  对象
  使用
  的
  任何
  运行时
  分配
  的
  缓冲区。

* 如果
  对象
  本身
  是
  动态
  分配
  的，
  对象
  的
  内存
  将
  被
  释放。

对象
放置
****************

仅
由
监督
线程
使用
的
内核
对象
没
有限制，
可以
位于
二进制
的
任何
地方，
甚至
可以
声明
在
栈
上。
但是，
为了
防止
用户
线程
的
意外
或
故意
破坏，
它们
不得
位于
用户
线程
有
直接
访问
权限
的
任何
内存
中。

为了
静态
内核
对象
能
通过
系统
调用
API
被
用户
线程
使用，
必须
满足
关于
内核
对象
如何
声明
的
若干
条件：

* 对象
  必须
  在
  构建
  时
  声明
  为
  顶层
  全局
  变量，
  使得
  它
  出现在
  ELF
  符号
  表
  中。
  允许
  以
  static
  作用域
  声明
  内核
  对象。
  构建
  后
  脚本
  :ref:`gen_kobject_list.py`
  扫描
  生成
  的
  ELF
  文件
  以
  查找
  内核
  对象，
  并
  将
  其
  内存
  地址
  放置
  在
  内核
  对象
  元数据
  的
  特殊
  表
  中。
  内核
  对象
  可以
  是
  数组
  的
  成员
  或
  嵌入
  在
  其他
  数据
  结构
  中。

* 内核
  对象
  必须
  位于
  为
  内核
  保留
  的
  内存
  中。
  它们
  不得
  位于
  任何
  用户
  可
  访问
  的
  内存
  分区
  中。

* 为
  内核
  对象
  保留
  的
  任何
  内存
  必须
  专门
  用于
  该
  对象。
  内核
  对象
  不得
  是
  union
  数据
  类型
  的
  成员。

被
找到
但
不
满足
上述
条件
的
内核
对象
将
不
被
包含
在
生成
的
表
中，
该
表
用于
验证
从
用户
模式
传入
的
内核
对象
指针。

:ref:`gen_kobject_list.py`
脚本
的
调试
输出
在
调试
为什么
某些
对象
意外
不
被
跟踪
时
可能
有用。
如果
脚本
使用
``--verbose``
标志
运行，
或
构建
系统
以
详细
输出
调用，
将
打印
此
信息。

动态
对象
***************

如果
启用了
:kconfig:option:`CONFIG_DYNAMIC_OBJECTS`，
内核
对象
也
可以
在
运行时
分配。
在
此
情况
下，
可以
使用
:c:func:`k_object_alloc`
API
从
调用
线程
的
资源
池
实例化
对象。
此类
分配
可能
被
跟踪
为
引用
计数
的
对象，
在
失去
所有
引用
时
被
释放。

如何
跟踪
对象
=================

内核
对象
的
跟踪
基于
其
类型。
核心
内核
对象
和
线程
栈
按
其
结构
体
类型
跟踪，
驱动程序
实例
按
其
子系统
跟踪。

创建
新
核心
内核
对象
================================

* 在
  ``scripts/build/gen_kobject_list.py``
  中，
  将
  结构
  体
  的
  名称
  添加
  到
  :py:data:`kobjects`
  列表。

新
结构
体
的
实例
现在
应该
被
跟踪。

创建
新
驱动程序
子系统
内核
对象
============================================

所有
驱动程序
实例
都是
:c:struct:`device`。
它们
通过
其
设置
的
API
结构
体
进行
区分。

* 在
  ``scripts/build/gen_kobject_list.py``
  中，
  将
  新
  子系统
  的
  API
  结构
  体
  名称
  添加
  到
  :py:data:`subsystems`
  列表。

新
子系统
的
驱动程序
实例
现在
应该
被
跟踪。

选项
