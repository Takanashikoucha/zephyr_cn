内存堆
############

Zephyr 提供一系列允许线程动态分配内存的工具。

同步堆分配器
***************************

创建堆
==============

定义堆最简单的方式是静态定义，使用
:c:macro:`K_HEAP_DEFINE` 宏。这会创建一个带给定名称的
静态 :c:struct:`k_heap` 变量，管理指定大小的内存区域。

也可以用 :c:func:`k_heap_init` 创建堆，
以管理应用控制的任意内存区域。

分配内存
================

内存可以用 :c:func:`k_heap_alloc` 从堆中分配，
传入堆对象的地址和期望的字节数。
此函数类似标准 C 的 ``malloc()``，
在分配失败时返回 NULL 指针。

堆支持阻塞操作，允许线程睡眠直到内存可用。
最后一个参数是 :c:type:`k_timeout_t` 超时值，
指示线程在返回之前可以睡眠多久，
或者常量超时值 :c:macro:`K_NO_WAIT` 或 :c:macro:`K_FOREVER` 之一。

当需要特定对齐的块时，:c:func:`k_heap_aligned_alloc`
分配一个起始地址为调用者提供的 2 的幂对齐倍数的块。
:c:func:`k_heap_calloc` 分配并零初始化一个数组。

现有分配的大小可以用 :c:func:`k_heap_realloc` 更改，
它返回请求大小的块，同时保留内容，
保留范围到旧大小和新大小中较小者为止。
与标准 C 的 ``realloc()`` 一样，返回的指针
可能与原始指针不同。

释放内存
================

用 :c:func:`k_heap_alloc` 分配的内存必须用
:c:func:`k_heap_free` 释放。类似标准 C 的 ``free()``，
提供的指针必须是 ``NULL`` 值，
或同一堆之前由 :c:func:`k_heap_alloc` 返回的指针。
释放 ``NULL`` 值被定义为无效果。

枚举堆
================

所有用 :c:macro:`K_HEAP_DEFINE` 静态定义的堆
都放在专用链接器段中，这使得可以在运行时枚举它们。
:c:func:`k_heap_array_get` 返回静态定义的堆数组的地址
以及该数组包含的条目数。这主要对需要检查
系统中每个堆的测量和诊断有用。

底层堆分配器
************************

:c:struct:`k_heap` 抽象的底层实现
提供了一个名为 :c:struct:`sys_heap` 的数据结构。
它实现完全相同的分配语义，
但不提供任何内核同步工具。它可用于
希望在同步不可用或更复杂的上下文
（例如用户空间）中管理自己内存块的应用。
与 ``k_heap`` 不同，对单个堆的所有 ``sys_heap``
函数调用必须由调用者序列化。
不允许从不同线程同时使用。

实现
==============

内部，``sys_heap`` 内存块被划分为 8 字节的
"块（chunk）"。所有分配都从一个连续的
块区域中进行。每个分配或空闲块（unused block）
的第一个块前面都有一个块头（chunk header），
保存块的长度、物理内存中下一个较低
（"left"）块的长度、指示该块是否正在使用的位，
以及指向"空闲列表（free list）"中前一个和后一个
块的块索引链接指针（空闲块被添加到该列表中）。

堆代码合理注意避免碎片化。空闲块列表
按大小存储在"桶（bucket）"中，每个桶存储
一个 2 的幂范围内的块（即 3-4 块的桶、
5-8 块的桶、9-16 块的桶等...），
这使得新分配可以从最小/最碎片化的可用块中进行。
此外，当分配被释放并添加到堆时，
它们会自动与相邻的空闲块合并，以防止碎片化。

所有元数据都存储在连续堆内存块的开头，
包括变长的桶列表头列表（其长度取决于堆大小）。
唯一需要的外部内存是 :c:struct:`sys_heap` 结构体本身。

``sys_heap`` 函数是未同步的。任何使用者
都必须注意防止并发访问。一次只能有一个上下文
位于某个 API 函数内部。

堆代码注意提供高性能和可靠的延迟。
所有 ``sys_heap`` API 函数保证在常量时间内完成。
在典型架构上，它们都会在 1-200 个周期内完成。
一个复杂性在于：为一次分配搜索最小桶大小
（即"可能适合"的空闲块集合）
有编译时的迭代次数上限，以防止无界的列表搜索，
代价是牺牲一定的碎片化抗性。
此 :kconfig:option:`CONFIG_SYS_HEAP_ALLOC_LOOPS` 值
可由用户在构建时选择，默认值为 3。

多堆包装工具
**************************

``sys_heap`` 工具要求所有被管理的内存
位于单个连续块中。复杂的微控制器应用
通常有更复杂的内存布局，但仍希望将其
动态管理为一个"堆"。例如，内存可能
作为分离的不连续区域存在，不同区域可能
有不同的缓存、性能或功耗行为，外设设备可能
只能对某些区域执行 DMA 等...

对于这些情况，Zephyr 提供了一个 ``sys_multi_heap`` 工具。
实际上，它是一组一个或多个 ``sys_heap`` 对象的简单包装器。
它应在子堆之后通过 :c:func:`sys_multi_heap_init` 初始化，
之后每个堆都可以通过 :c:func:`sys_multi_heap_add_heap`
添加到被管理的集合中。不提供销毁工具；
与 ``sys_heap`` 一样，想要销毁多堆的应用
只需确保所有已分配的块都被释放
（或至少永远不会再被使用），
然后将底层内存重新用于其他用途即可。

它有一对分配入口点：
:c:func:`sys_multi_heap_alloc` 和
:c:func:`sys_multi_heap_aligned_alloc`。
它们的行为与 ``sys_heap`` 中类似名称的函数相同，
只是它们还接受一个不透明的"配置"参数。
该指针不被多堆代码本身检查；
相反，它被传递给初始化时提供的回调函数。
此应用提供的回调负责从被管理的堆之一
进行底层分配，可以按任意方式使用
配置参数来做出该决策。

要修改已分配缓冲区的大小（无论缩小
还是扩大），可以使用
:c:func:`sys_multi_heap_realloc` 和
:c:func:`sys_multi_heap_aligned_realloc` API。
如果缓冲区无法在其当前所在的堆上扩大，
配置参数指定的任何合格堆都可以被使用。

未使用时，多堆可以通过
:c:func:`sys_multi_heap_free` 释放。
应用无需传递配置参数。
从任何被管理的 ``sys_heap`` 对象分配的内存
都可以用相同方式释放。

系统堆
***********

:dfn:`系统堆` 是一个预定义的内存分配器，
允许线程以 :c:func:`malloc` 类似的方式
从公共内存区域动态分配内存。

仅定义单个系统堆。与其他堆或内存池不同，
系统堆不能用其内存地址直接引用。

系统堆的大小可以配置为任意大小，
受空间可用性限制。

线程可以通过调用 :c:func:`k_malloc`
动态分配一块堆内存。所分配块的地址
保证对齐到指针大小的倍数。
如果找不到合适的堆内存块，则返回 ``NULL``。

当线程用完一块堆内存时，
可以通过调用 :c:func:`k_free`
将该块释放回系统堆。

定义堆内存池
=============================

堆内存池的大小用
:kconfig:option:`CONFIG_HEAP_MEM_POOL_SIZE` 配置选项指定。

默认情况下，堆内存池大小为零字节。
此值指示内核不定义堆内存池对象。
最大大小受系统中可用内存量限制。
如果指定的大小无法被支持，
项目构建将在链接阶段失败。

此外，每个子系统（开发板、驱动、库等）
都可以通过定义前缀为 ``HEAP_MEM_POOL_ADD_SIZE_``
的 Kconfig 选项设置自定义要求（此值以字节为单位）。
如果多个子系统指定了自定义值，
这些值的总和将被用作最小要求。
如果应用尝试设置小于最小值的值，
该值将被忽略，改用最小值。

要强制使用小于最小值的值，
应用可以启用 :kconfig:option:`CONFIG_HEAP_MEM_POOL_IGNORE_MIN`
选项。这在优化堆大小、且最小要求
可以被更准确确定的特定应用场景中可能有用。

分配内存
================

一块堆内存通过调用 :c:func:`k_malloc` 分配。

以下代码分配 200 字节的堆内存块，
然后用零填充它。如果未获得合适的块，
则发出警告。

.. code-block:: c

    char *mem_ptr;

    mem_ptr = k_malloc(200);
    if (mem_ptr != NULL)) {
        memset(mem_ptr, 0, 200);
	...
    } else {
        printf("Memory not allocated");
    }

释放内存
================

一块堆内存通过调用 :c:func:`k_free` 释放。

以下代码分配 75 字节的内存块，
然后在其不再需要时释放它。

.. code-block:: c

    char *mem_ptr;

    mem_ptr = k_malloc(75);
    ... /* 使用内存块 */
    k_free(mem_ptr);

建议用途
================

用堆内存池以 :c:func:`malloc` 类似的方式
动态分配内存。
