.. _heap_v2:

内存堆
############

Zephyr 提供了一组工具，允许线程
动态分配内存。

同步堆分配器
***************************

创建堆
================

定义堆最简单的方式是静态地，
用
:c:macro:`K_HEAP_DEFINE` 宏。
这会创建一个
静态的 :c:struct:`k_heap` 变量，
具有给定名称，
管理指定大小的
内存区域。

也可以用 :c:func:`k_heap_init`
创建堆来管理
任意
应用控制的
内存区域。

分配内存
================

可以用 :c:func:`k_heap_alloc`
从堆分配内存，
传入堆对象地址和
所需字节数。
该函数
类似于标准 C 的 ``malloc()``
，
分配失败时
返回
NULL 指针。

堆支持
阻塞操作，
允许线程
睡眠
直到
内存可用。
最后一个
参数是
:c:type:`k_timeout_t` 超时值，
指示线程
可以
睡眠
多久
才
返回，
或者
是
常量
超时值
:c:macro:`K_NO_WAIT`
或
:c:macro:`K_FOREVER`
之一。

当
需要
特定
对齐
的
块
时，
:c:func:`k_heap_aligned_alloc`
分配
一个
起始
地址
是
调用者
提供的
2 的
幂
对齐
倍数
的
块。
:c:func:`k_heap_calloc`
分配
并
零初始化
一个
数组。

可以用 :c:func:`k_heap_realloc`
改变
现有
分配
的
大小，
它
返回
请求
大小
的
块，
同时
保留
内容
（
至
旧
新
大小
中
较小
者
）。
与
标准
C 的
``realloc()``
一样，
返回
的
指针
可能
与
原始
指针
不同。

释放内存
================

用 :c:func:`k_heap_alloc`
分配的
内存
必须
用
:c:func:`k_heap_free`
释放。
类似
标准
C 的
``free()``
，
提供的
指针
必须
是
``NULL``
值
或
之前
由
同一
堆
的
:c:func:`k_heap_alloc`
返回
的
指针。
释放
``NULL``
值
被
定义
为
无
效果。

枚举堆
================

所有
用
:c:macro:`K_HEAP_DEFINE`
静态
定义
的
堆
被
放入
专用
链接器
段，
这
允许
在
运行时
枚举
它们。
:c:func:`k_heap_array_get`
返回
静态
定义
堆
的
数组
地址
及其
包含
的
条目
数。
这
主要
用于
需要
检查
系统中
每个
堆
的
测量
和
诊断。

低层堆分配器
************************

:c:struct:`k_heap`
抽象
的
底层
实现
由
一个
名为
:c:struct:`sys_heap`
的
数据结构
提供。
它
实现
完全
相同
的
分配
语义，
但
不提供
内核
同步
工具。
它
可供
想在
同步
不可用
或
更
复杂
的
上下文
（
例如
用户空间
）
中
管理
自己
内存
块
的
应用
使用。
与
``k_heap``
不同，
对
单个
堆
的
任何
``sys_heap``
函数
的
所有
调用
必须
由
调用者
序列化。
不允许
从
不同
线程
同时
使用。

实现
================

内部地，
``sys_heap``
内存
块
被
划分
为
8 字节
的
"块"
（
chunk
）。
所有
分配
都
从
连续
的
块
区域
中
做出。
每个
分配
或
未使用
块
的
第一个
块
之前
有一个
块
头
，
存储
块
的
长度、
物理
内存
中
下一个
较低
（
"左侧"
）
块
的
长度、
一个
指示
块
是否
在
使用
的
位、
以及
指向
"空闲
列表"
中
前一个
和
后一个
块的
块
索引
链接
指针
，
未使用
的
块
被
添加
到
该
列表。

堆
代码
合理
地
注意
避免
碎片化。
空闲
块
列表
按
大小
存储
在
"桶"
（
bucket
）
中，
每个
桶
存储
一个
2 的
幂
范围内
的
块
（
即
一个
桶
存
3-4
块
的
块，
另一个
存
5-8、
9-16
等
）
，
这
允许
新
分配
从
最小/碎片化
最严重
的
可用
块
中
做出。
此外，
当
分配
被
释放
并
添加
到
堆
时，
它们
自动
与
相邻
的
空闲
块
合并
以
防止
碎片化。

所有
元数据
存储
在
连续
堆
内存
块
的
开头，
包括
变长
的
桶
列表
头
列表
（
依赖
于
堆
大小
）。
唯一
需要
的
外部
内存
是
:c:struct:`sys_heap`
结构体
本身。

``sys_heap``
函数
是
无
同步
的。
任何
使用者
必须
注意
防止
并发
访问。
同一
时间
只有
一个
上下文
可以
在
一个
API
函数
内。

堆
代码
注意
提供
高
性能
和
可靠
延迟。
所有
``sys_heap``
API
函数
保证
在
常数
时间
内
完成。
在
典型
架构
上，
它们
都
在
1-200
个
周期
内
完成。
一个
复杂性
是
为
分配
搜索
最小
桶
大小
（
"可能
装得下"
的
空闲
块
集合
）
有
一个
编译
时
迭代
上限，
以
防止
无
界
列表
搜索，
代价
是
一些
碎片化
抵抗
力。
这个
:kconfig:option:`CONFIG_SYS_HEAP_ALLOC_LOOPS`
值
可以
由
用户
在
构建
时
选择，
默认
为
3。

多堆
包装
工具
**************************

``sys_heap``
工具
要求
所有
被
管理
的
内存
在
单个
连续
块
中。
复杂
的
微控制器
应用
通常
有
更
复杂
的
内存
布局，
仍
希望
将其
动态
管理
为
"堆"
。
例如，
内存
可能
存在
为
分离
的
不
连续
区域，
不同
区域
可能
有
不同
的
缓存、
性能
或
功耗
行为，
外设
设备
可能
只能
对
某些
区域
执行
DMA
等
。

对于
那些
情况，
Zephyr
提供
一个
``sys_multi_heap``
工具。
实际上
这是
一组
一个
或
多个
``sys_heap``
对象
的
简单
包装。
它
应
在
其
子
堆
之后
通过
:c:func:`sys_multi_heap_init`
初始化，
之后
每个
堆
可以
通过
:c:func:`sys_multi_heap_add_heap`
添加
到
被
管理
的
集合
中。
不
提供
销毁
工具
；
与
``sys_heap``
一样，
想
销毁
多
堆
的
应用
只需
确保
所有
已
分配
的
块
被
释放
（
或
至少
永远
不再
被
使用
）
，
并
将
底层
内存
改作
其他
用途。

它
有
一对
分配
入口
，
:c:func:`sys_multi_heap_alloc`
和
:c:func:`sys_multi_heap_aligned_alloc`
。
它们
与
同名
的
``sys_heap``
函数
行为
完全
相同，
只是
还
接受
一个
不透明
的
"配置"
参数。
该
指针
不
被
多
堆
代码
本身
检查
；
相反
它
被
传递给
初始化
时
提供
的
回调
函数。
这个
应用
提供
的
回调
负责
从
被
管理
的
堆
之一
做
底层
分配，
可以
按
任意
方式
使用
配置
参数
来
做
该
决策。

对于
修改
已
分配
缓冲区
的
大小
（
无论
缩小
还是
扩大
），
可以
使用
:c:func:`sys_multi_heap_realloc`
和
:c:func:`sys_multi_heap_aligned_realloc`
API。
如果
缓冲区
无法
在
其
当前
所在
的
堆
上
扩大，
可以
使用
配置
参数
指定的
任何
合格
堆。

当
未
使用
时，
多
堆
可以
通过
:c:func:`sys_multi_heap_free`
释放。
应用
不
需要
传递
配置
参数。
从
任何
被
管理
的
``sys_heap``
对象
分配
的
内存
可以
用
同样
的
方式
释放。

系统堆
***********

:dfn:`系统堆`
是
一个
预定义
的
内存
分配器，
允许
线程
以
类似
:c:func:`malloc`
的
方式
从
公共
内存
区域
动态
分配
内存。

只
定义
了
单个
系统
堆。
与
其他
堆
或
内存
池
不同，
系统
堆
无法
通过
其
内存
地址
直接
引用。

系统
堆
的
大小
可以
配置
为
任意
大小，
受
空间
可用性
限制。

线程
可以
通过
调用
:c:func:`k_malloc`
动态
分配
一块
堆
内存。
已
分配
块
的
地址
保证
对齐
到
指针
大小
的
倍数。
如果
找不到
合适
的
堆
内存
块
，
返回
``NULL``
。

当
线程
用完
一块
堆
内存
，
可以
通过
调用
:c:func:`k_free`
将该
块
释放
回
系统
堆。

定义堆内存池
=============================

堆
内存
池
的
大小
用
:kconfig:option:`CONFIG_HEAP_MEM_POOL_SIZE`
配置
选项
指定。

默认
情况下，
堆
内存
池
大小
为
零
字节。
该
值
指示
内核
不
定义
堆
内存
池
对象。
最大
大小
受
系统中
可用
内存
量
限制。
如果
指定
的
大小
无法
支持，
项目
构建
会
在
链接
阶段
失败。

此外，
每个
子系统
（
开发板、
驱动、
库
等
）
可以
通过
定义
带
前缀
``HEAP_MEM_POOL_ADD_SIZE_``
的
Kconfig
选项
设置
自定义
要求
（
该
值
以
字节
为单位
）。
如果
多个
子系统
指定
自定义
值，
这些
值
的
总和
将
被
用作
最低
要求。
如果
应用
尝试
设置
小于
最低
值
的
值，
这
将
被
忽略，
改为
使用
最低
值。

要
强制
使用
小于
最低
值
的
值，
应用
可以
启用
:kconfig:option:`CONFIG_HEAP_MEM_POOL_IGNORE_MIN`
选项。
在
优化
堆
大小
且
可以
更
准确
确定
特定
应用
的
最低
要求
时，
这
可能
很有
用。

分配内存
================

通过
调用
:c:func:`k_malloc`
分配
一块
堆
内存。

以下
代码
分配
一块
200
字节
的
堆
内存，
然后
用
零
填充
它。
如果
未
获得
合适
的
块
，
发出
警告。

.. code-block:: c

    char *mem_ptr;

    mem_ptr = k_malloc(200);
    if (mem_ptr != NULL)) {
        memset(mem_ptr, 0, 200);
	...
    } else {
        printf("Memory not allocated");
    }

释放内存
================

通过
调用
:c:func:`k_free`
释放
一块
堆
内存。

以下
代码
分配
一块
75
字节
的
内存，
然后
在
不再
需要
时
释放
它。

.. code-block:: c

    char *mem_ptr;

    mem_ptr = k_malloc(75);
    ... /* use memory block */
    k_free(mem_ptr);

建议用途
================

使用
堆
内存
池
以
类似
:c:func:`malloc`
的
方式
动态
分配
内存。

配置选项
=====================

相关
配置
选项
：

* :kconfig:option:`CONFIG_HEAP_MEM_POOL_SIZE`
