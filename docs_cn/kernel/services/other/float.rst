浮点服务
#######################

在支持浮点寄存器的板级配置上，内核允许线程使用浮点寄存器。

.. note::
    浮点服务目前仅对以下板级可用：基于支持浮点扩展（Floating Point
    Extension）的 ARM Cortex-M SoC 的板级、Intel x86 架构、SPARC 架构，
    以及支持浮点扩展的 ARCv2 SoC。所提供的
    服务是架构相关的。

    内核不支持 ISR 使用浮点寄存器。

.. contents::
    :local:
    :depth: 2

概念
********

可以将内核配置为仅向应用提供所需的浮点服务。
支持三种运行模式，描述如下。此外，
内核对 SSE 寄存器的支持可以按需包含或省略。

线程参与浮点上下文保存的情况也可以在运行时进行管理。
:c:func:`k_float_enable` 为线程启用保存并接收
选项——例如 :c:macro:`K_FP_REGS` 和 :c:macro:`K_SSE_REGS`——
以选择保存哪些寄存器组，而 :c:func:`k_float_disable`
再次关闭保存。在未实现浮点
上下文管理的目标平台上，这些例程返回 ``-ENOTSUP``；
如果请求在其他方面无效且无法执行，则返回
``-EINVAL``。

无 FP 寄存器模式
====================

当应用没有使用浮点寄存器的线程时，使用此模式。
它是内核的默认浮点服务模式。

如果某个线程使用了任何浮点寄存器，
内核会生成致命错误条件并中止该线程。

非共享 FP 寄存器模式
==========================

当应用只有一个使用浮点寄存器的线程时，
使用此模式。

在 x86 平台上，内核初始化浮点寄存器，使其
可被任何线程使用（在 ARM Cortex-M 平台和
ARCv2 平台上跳过初始化）。每当发生
上下文切换时，浮点寄存器保持原样不变。

.. note::
    如果两个或更多线程试图使用
    浮点寄存器，行为是未定义的，因为内核不会尝试检测
    （或阻止）多个线程使用这些寄存器。

共享 FP 寄存器模式
========================

当应用有两个或更多使用浮点寄存器的线程时，
使用此模式。根据底层 CPU 架构的不同，
内核支持以下线程子类中的一种或多种：

* non-user（非用户）：不能使用任何浮点寄存器的线程

* FPU user（FPU 用户）：可以使用标准浮点寄存器的线程

* SSE user（SSE 用户）：既可以使用标准浮点寄存器
  又可以使用 SSE 寄存器的线程

内核初始化并启用对浮点寄存器的访问，
使其可被任何线程使用，然后在
上下文切换期间保存和恢复这些寄存器，
以确保每个 FPU 用户或 SSE 用户执行
的计算不会受到其他用户执行的影响。

ARM Cortex-M 架构（带浮点扩展）
--------------------------------------------------------------

.. note::
    在 ARM Cortex-M 上，共享 FP 寄存器模式
    是默认的浮点服务模式。

在带浮点扩展的 ARM Cortex-M 架构上，
启用共享 FP 寄存器模式时，内核
将所有线程都视为 FPU 用户。
这意味着任何线程都被允许访问浮点寄存器。
ARM 内核在线程第一次访问浮点寄存器时
自动检测该线程正在使用这些寄存器。

使用下面列出的技术之一，
为打算使用 FP 寄存器的线程预先打标签（pretag）。

* 静态创建的 ARM 线程可以通过向 :c:macro:`K_THREAD_DEFINE`
  传递 :c:macro:`K_FP_REGS` 选项来预先打标签。

* 动态创建的 ARM 线程可以通过向 :c:func:`k_thread_create`
  传递 :c:macro:`K_FP_REGS` 选项来预先打标签。

使用 :c:macro:`K_FP_REGS` 选项为线程预先打标签
会指示基于 MPU 的栈保护机制正确配置
线程保护区域（guard region）的大小，
以始终保证栈溢出检测，
并在创建线程时为给定线程启用惰性压栈（lazy stacking）。

在线程上下文切换期间，ARM 内核保存*被调用者保存*（callee-saved）
浮点寄存器（如果切出的线程一直在使用它们）。
此外，*调用者保存*（caller-saved）浮点寄存器
被保存在线程栈上。如果切入的线程一直在使用浮点
寄存器，内核恢复切入线程的*被调用者保存* FP 寄存器，
*调用者保存*的 FP 上下文从线程栈恢复。
因此，内核不会保存或恢复未使用 FP 寄存器的线程的
FP 上下文。

每个打算使用浮点寄存器的线程必须额外提供
72 字节的栈空间，用于保存被调用者保存的 FP 上下文。

`惰性压栈
<https://developer.arm.com/documentation/dai0298/a>`_
目前在 ARM Cortex-M 架构上的 Zephyr 应用中已启用，
当浮点上下文处于活动状态时，
可将中断延迟降至最低。

当未启用基于 MPU 的栈保护机制时，惰性压栈
在 Zephyr 应用中始终处于活动状态。当启用基于 MPU 的栈保护
时，关于惰性压栈适用以下规则：

* 对于预先用 :c:macro:`K_FP_REGS` 打了标签的线程，
  默认启用惰性压栈
* 对于未预先用 :c:macro:`K_FP_REGS` 打标签的线程，
  一旦内核检测到它们正在使用浮点寄存器，
  即动态启用惰性压栈。


如果某个 ARM 线程不再需要
使用浮点寄存器，它可以调用 :c:func:`k_float_disable`。
这会指示内核
在线程上下文切换期间不保存或恢复其 FP 上下文。

ARM64 架构
------------------

.. note::
    在 ARM64 上，共享 FP 寄存器模式
    是默认的浮点服务模式。编译器可以自由地优化
    使用 FP/SIMD 寄存器的代码，且 memcpy 等库函数
    已知会用到这些寄存器。

在 ARM64（Aarch64）架构上，内核逐个案例地将
每个线程视为 FPU 用户。上下文切换期间
使用"惰性保存"算法，仅在绝对必要时
才更新浮点寄存器。例如，从
FPU 用户切换到非用户线程、再切回原 FPU 用户时，
寄存器*不会*被保存。

ISR 使用 FPU 寄存器受支持但不推荐。当
ISR 使用浮点或 SIMD 寄存器时，该访问会被陷入（trapped），
当前 FPU 用户上下文被保存在线程对象中，
ISR 在禁用中断的状态下恢复，以防止另一个 IRQ 中断该 ISR
并可能再次请求 FPU 使用。由于 ISR 没有持久的
寄存器上下文，也没有保存 ISR FPU 上下文
的机制，因此需要禁用 IRQ。

启用共享 FP 寄存器模式时，
每个线程对象会增大 512 字节。

ARCv2 架构
------------------

在 ARCv2 架构上，内核将每个线程视为
非用户或 FPU 用户，线程必须通过以下
技术之一打上标签。

* 静态创建的 ARC 线程可以通过向 :c:macro:`K_THREAD_DEFINE`
  传递 :c:macro:`K_FP_REGS` 选项来打标签。

* 动态创建的 ARC 线程可以通过向 :c:func:`k_thread_create`
  传递 :c:macro:`K_FP_REGS` 来打标签。

如果某个 ARC 线程不再需要
使用浮点寄存器，它可以调用 :c:func:`k_float_disable`。
这会指示内核
在线程上下文切换期间不保存或恢复其 FP 上下文。

在线程上下文切换期间，ARC 内核保存*被调用者保存*
浮点寄存器（如果切出的线程一直在使用它们）。
此外，*调用者保存*浮点寄存器
被保存在线程栈上。如果切入的线程一直在使用浮点
寄存器，内核恢复切入线程的*被调用者保存* FP 寄存器，
*调用者保存*的 FP 上下文从线程栈恢复。
因此，内核不会保存或恢复未使用 FP 寄存器的线程的
FP 上下文。加载和存储浮点寄存器需要额外
16 字节（单精度浮点硬件）或 32 字节（双精度浮点硬件）
的栈空间。

RISC-V 架构
-------------------

在 RISC-V 架构上，内核逐个案例地将每个线程视为 FPU
用户，FPU 访问按需分配。
上下文切换期间使用"惰性保存"算法，
仅在绝对必要时才更新
浮点寄存器。
例如，从 FPU 用户切换到非用户线程（或在其调度时间片内
不触碰 FPU 的 FPU 用户）、再切回原 FPU 用户时，
FPU 寄存器*不会*被保存。

ISR 使用 FPU 寄存器受支持但不推荐。当
ISR 使用浮点或 SIMD 寄存器时，该访问会被陷入，
当前 FPU 用户上下文被保存在线程对象中，
ISR 在禁用中断的状态下恢复，以防止另一个 IRQ 中断该 ISR
并可能再次请求 FPU 使用。由于 ISR 没有持久的
寄存器上下文，也没有保存 ISR FPU 上下文
的机制，因此需要禁用 IRQ。

作为一项优化，当重新调度一个"活动 FPU 用户"线程时，
如果其 FPU 上下文因另一个线程使用 FPU 而被保存，
则提前恢复其 FPU 上下文。当一个线程在被调度出去之前
在最近一次调度时间片内使 FPU 状态变为"脏"（dirty）时，
即被指定为活动 FPU 用户。因此，如果某线程在其
调度时间片内未修改 FPU 状态，且之后另一线程
为自己占用 FPU，则第一个线程将受到按需机制的约束，
其 FPU 上下文不会被恢复，直到它再次尝试访问。
但如果该线程在被调度出去之前修改了 FPU，
那么它重新被调度回来时很可能继续使用 FPU，
提前恢复其 FPU 上下文可省去否则将发生的
异常陷入开销。

启用共享 FP 寄存器模式时，
每个线程对象会增大 136 字节（单精度浮点
硬件）或 264 字节（双精度浮点硬件）。

SPARC 架构
------------------

在 SPARC 架构上，内核将每个线程视为
非用户或 FPU 用户，线程必须通过以下
技术之一打上标签：

* 静态创建的线程可以通过向 :c:macro:`K_THREAD_DEFINE`
  传递 :c:macro:`K_FP_REGS` 选项来打标签。

* 动态创建的线程可以通过向 :c:func:`k_thread_create`
  传递 :c:macro:`K_FP_REGS` 来打标签。

在中断处理程序退出时的线程上下文切换期间，
SPARC 内核保存*所有*浮点寄存器
（如果切出的线程中 FPU 已启用）。
浮点寄存器被保存在线程栈上。
当线程上下文被恢复时，仅当它们在上下文保存时被保存过，
浮点寄存器才会被恢复。浮点寄存器的保存和恢复
是同步的，因此不是惰性的。
ISR 被调用时 FPU 始终被禁用
（与 :kconfig:option:`CONFIG_FPU_SHARING` 无关）。

通过 :c:func:`k_float_disable` 禁用浮点的功能未实现。

使用 :kconfig:option:`CONFIG_FPU_SHARING` 时，
每个 FPU 用户线程需要 136 字节的栈空间
来加载和存储浮点寄存器。
未使用 :kconfig:option:`CONFIG_FPU_SHARING` 时
不需要额外栈空间。

x86 架构
----------------

在 x86 架构上，内核逐个案例地将每个线程视为
非用户、FPU 用户或 SSE 用户。
上下文切换期间使用"惰性保存"算法，
仅在绝对必要时才更新浮点寄存器。
例如，从 FPU 用户切换到非用户线程、再切回原
FPU 用户时，寄存器*不会*被保存。
下表说明线程必须提供多少额外栈空间
才能正确保存寄存器。

=========== =============== ==========================
线程类型    FP 寄存器使用   所需额外栈空间
=========== =============== ==========================
协作式      任意            0 字节
抢占式      无              0 字节
抢占式      FPU             108 字节
抢占式      SSE             464 字节
=========== =============== ==========================

x86 内核在线程第一次访问浮点寄存器时
自动检测该线程正在使用这些寄存器。
如果内核被配置为支持 SSE 寄存器，线程
被标记为 SSE 用户；否则（不支持 SSE 寄存器时）
被标记为 FPU 用户。如果这会导致一个
FPU 用户线程被标记为 SSE 用户，或者应用
想避免线程自动打标签所涉及的异常
处理开销，就可以使用下面列出的技术之一
为线程预先打标签。

* 静态创建的 x86 线程可以通过向
  :c:macro:`K_THREAD_DEFINE` 传递
  :c:macro:`K_FP_REGS` 或 :c:macro:`K_SSE_REGS` 选项来预先打标签。

* 动态创建的 x86 线程可以通过向
  :c:func:`k_thread_create` 传递
  :c:macro:`K_FP_REGS` 或 :c:macro:`K_SSE_REGS` 选项来预先打标签。

* 已创建的 x86 线程在启动后可以
  通过向 :c:func:`k_float_enable` 传递
  :c:macro:`K_FP_REGS` 或 :c:macro:`K_SSE_REGS` 选项
  为自己预先打标签。

如果某个 x86 线程不常使用浮点寄存器，
它可以调用 :c:func:`k_float_disable` 移除其
FPU 用户或 SSE 用户标签。
这消除了内核在上下文切换期间
为保存浮点寄存器内容而采取措施的需要
（在无需保存时）。
当线程再次需要使用浮点寄存器时，
可以通过调用 :c:func:`k_float_enable`
重新将自己标记为 FPU 用户或 SSE 用户。

实现
**************

执行浮点运算
====================================

如果内核配置正确，线程使用浮点运算
无需特殊编码。

下面的代码展示了一个例程如何使用浮点运算
来计算一系列整数值平均值时
避免溢出问题。

.. code-block:: c

    int average(int *values, int num_values)
    {
        double sum;
        int i;

        sum = 0.0;

        for (i = 0; i < num_values; i++) {
            sum += *values;
            values++;
        }

        return (int)((sum / num_values) + 0.5);
    }

建议用法
**************

当应用需要执行浮点运算时，
使用内核浮点服务。

配置选项
*********************

要配置非共享 FP 寄存器模式，启用 :kconfig:option:`CONFIG_FPU`
配置选项，并保持 :kconfig:option:`CONFIG_FPU_SHARING` 配置
选项禁用。

要配置共享 FP 寄存器模式，同时启用 :kconfig:option:`CONFIG_FPU`
配置选项和 :kconfig:option:`CONFIG_FPU_SHARING` 配置选项。
此外，确保任何使用浮点寄存器的线程
都有足够的额外栈空间，用于在上下文切换期间
保存浮点寄存器值，如上文所述。

对于 x86，使用 :kconfig:option:`CONFIG_X86_SSE` 配置选项启用
对 SSEx 指令的支持。
