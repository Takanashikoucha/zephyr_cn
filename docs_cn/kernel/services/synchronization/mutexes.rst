互斥锁
#######

:dfn:`互斥锁` 是一种实现传统可重入互斥锁的内核对象。互斥锁通过确保对资源的互斥访问，允许多个线程安全共享关联的硬件或软件资源。

.. contents::
    :local:
    :depth: 2

概念
********

可以定义任意数量的互斥锁（仅受可用 RAM 限制）。每个互斥锁由其内存地址引用。

互斥锁具有以下关键属性：

* 一个**锁计数**，指示已锁定该互斥锁的线程将其锁定的次数。计数为零表示互斥锁未锁定。

* 一个**属主线程**，标识已锁定该互斥锁的线程（当它被锁定时）。

互斥锁在使用之前必须被初始化。这将其锁计数设置为零。

需要使用共享资源的线程必须首先通过**锁定**关联的互斥锁获得访问它的独占权。如果互斥锁已被另一个线程锁定，请求线程可以选择等待互斥锁被解锁。

锁定互斥锁后，线程可以安全地使用关联资源，直到所需时间；然而，良好实践是尽可能短地持有锁，以避免对想要使用该资源的其他线程产生负面影响。当线程不再需要该资源时，必须**解锁**互斥锁以允许其他线程使用资源。

当互斥锁被锁定或有线程在其上等待时，不得释放该互斥锁或复用其内存。嵌入在动态分配对象中的互斥锁必须在该对象释放前解锁；否则属主线程将被留下跟踪一个不再属于它的内存中的互斥锁。

任意数量的线程可以同时等待一个锁定的互斥锁。当互斥锁变为未锁定时，它将被等待时间最长的最高优先级线程锁定。

.. note::
    互斥锁对象*不*为中断服务例程（ISR）使用而设计。

可重入锁定
=================

线程被允许锁定它已经锁定的互斥锁。这允许线程在其执行过程中，在互斥锁可能已锁定也可能未锁定的点上访问关联资源。

被线程重复锁定的互斥锁必须被解锁相同次数后，互斥锁才完全解锁，从而可以被另一个线程获取。

优先级继承
====================

已锁定互斥锁的线程有资格获得:dfn:`优先级继承`。这意味着如果更高优先级的线程开始在互斥锁上等待，内核将*临时*提升该线程的优先级。这允许属主线程以与等待线程相同的优先级执行，从而更快地完成其工作并释放互斥锁。一旦互斥锁被解锁，解锁线程将其优先级重置为锁定该互斥锁之前的级别。

.. note::
    :kconfig:option:`CONFIG_PRIORITY_CEILING` 配置选项限制内核可因优先级继承将线程优先级提升的高度。默认值 -128 允许无限制。将其设置为等于或低于空闲线程优先级的优先级级别可禁用该功能。

线程在任何互斥锁相关提升之前的优先级在首次提升时保存在线程本身，且它持有的每个互斥锁在每线程列表中跟踪。每次更高优先级的线程在互斥锁上等待，内核调整属主线程的优先级。当属主线程释放锁（或高优先级等待线程超时），内核重新扫描线程剩余持有的互斥锁，并从仍在任何互斥锁上等待的最高优先级等待者重新计算其优先级（如果没有剩余则回退到线程原始优先级）。无论持有的互斥锁以何种顺序解锁，这都给出正确结果。

如果某个互斥锁的属主本身阻塞在等待另一个互斥锁上，优先级提升沿该属主链传播，使得每个阻止等待者进展的线程依次提升，直到每次锁尝试遍历的链跳数达到实现定义的限制。超出该限制的属主保持其提升前的优先级，直到稍后的锁尝试再次遍历该链。

实现
**************

定义互斥锁
================

互斥锁使用 :c:struct:`k_mutex` 类型的变量来定义。然后必须通过调用 :c:func:`k_mutex_init` 进行初始化。

下面的代码定义并初始化一个互斥锁。

.. code-block:: c

    struct k_mutex my_mutex;

    k_mutex_init(&my_mutex);

或者，可以通过调用 :c:macro:`K_MUTEX_DEFINE` 在编译时定义并初始化互斥锁。

下面的代码与上面代码段效果相同。

.. code-block:: c

    K_MUTEX_DEFINE(my_mutex);

锁定互斥锁
=================

互斥锁通过调用 :c:func:`k_mutex_lock` 来锁定。

下面的代码基于上面的示例，如果互斥锁已被另一个线程锁定，则无限等待互斥锁变得可用。

.. code-block:: c

    k_mutex_lock(&my_mutex, K_FOREVER);

下面的代码最多等待 100 毫秒直到互斥锁变得可用，如果互斥锁未变得可用则给出警告。

.. code-block:: c

    if (k_mutex_lock(&my_mutex, K_MSEC(100)) == 0) {
        /* mutex successfully locked */
    } else {
        printf("Cannot lock XYZ display\n");
    }

解锁互斥锁
=================

互斥锁通过调用 :c:func:`k_mutex_unlock` 来解锁。

下面的代码基于上面的示例，解锁之前由线程锁定的互斥锁。

.. code-block:: c

    k_mutex_unlock(&my_mutex);

建议用法
**************

使用互斥锁为资源（如物理设备）提供独占访问。

配置选项
*********************

相关配置选项：

* :kconfig:option:`CONFIG_PRIORITY_CEILING`

Futex API 参考
*******************

:c:struct:`k_futex` 是一种设计为最小化内核参与的轻量级互斥原语。无竞争操作仅依赖对共享内存的原子访问。:c:struct:`k_futex` 不是内核对象，也不使用内核对象权限管理。它们驻留在用户内存中，可被任何对该内存有读写访问的线程使用。

.. doxygengroup:: futex_apis

用户态互斥锁 API 参考
*****************************

:c:struct:`sys_mutex` 的行为几乎与 :c:struct:`k_mutex` 完全相同，额外优势是 :c:struct:`sys_mutex` 实例可以驻留在用户内存中。当用户态未启用时，:c:struct:`sys_mutex` 的行为与 :c:struct:`k_mutex` 相同。
