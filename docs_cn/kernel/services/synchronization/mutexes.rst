互斥锁
#########

:dfn:`互斥锁`是一种实现传统可重入互斥锁的内核对象。
互斥锁通过确保对资源的互斥访问，
允许多个线程安全地共享关联的硬件或软件资源。

.. contents::
    :local:
    :depth: 2

概念
********

可以定义任意数量的互斥锁（仅受可用 RAM 限制）。
每个互斥锁由其内存地址引用。

互斥锁具有以下关键属性：

* 一个**锁计数**，指示持有该互斥锁的线程
  已将其锁定的次数。计数为零表示
  该互斥锁未被锁定。

* 一个**持有线程**，标识（当互斥锁
  被锁定时）已锁定该互斥锁的线程。

互斥锁在使用之前必须被初始化。
这将其锁计数设为零。

需要使用共享资源的线程必须首先
通过**锁定**关联的互斥锁来获取
对该资源的独占访问权。如果互斥锁
已被另一个线程锁定，请求线程
可以选择等待该互斥锁被解锁。

锁定互斥锁后，线程可以安全地
使用关联资源任意长时间；不过，
良好的实践是尽可能短暂地持有锁，
以避免对希望使用该资源的
其他线程产生负面影响。
当线程不再需要该资源时，
它必须**解锁**互斥锁
以允许其他线程使用该资源。

互斥锁在被锁定或有线程
在等待它时，不得被释放，
或其内存被复用。
嵌入在动态分配对象中的
互斥锁必须在该对象
被释放之前解锁；
否则持有线程将
继续跟踪一个
不再属于它的
内存中的互斥锁。

任意数量的线程可以
同时等待一个
已锁定的互斥锁。
当互斥锁变为未锁定时，
它随后被等待时间最长的
最高优先级线程锁定。

.. note::
    互斥锁对象*不*是
    设计给 ISR 使用的。

可重入锁定
=================

线程被允许锁定它
已经锁定的互斥锁。
这允许线程
在其执行的
某个时间点
访问关联资源，
而该时间点
互斥锁可能
也可能尚未
被锁定。

被线程
反复锁定的
互斥锁
必须被
解锁
相同
次数，
之后
互斥锁
才
完全
解锁，
从而
可以
被
另一个
线程
获取。

优先级继承
====================

已锁定互斥锁的线程
有资格获得 :dfn:`优先级继承`。
这意味着内核将*临时*提升
该线程的优先级，
如果更高优先级线程
开始等待该互斥锁。
这允许持有线程
以与等待线程相同的优先级
执行，从而更快速地
完成其工作并释放互斥锁。
一旦互斥锁被解锁，
解锁线程将其优先级
重置为锁定该互斥锁
之前的级别。

.. note::
    :kconfig:option:`CONFIG_PRIORITY_CEILING` 配置选项
    限制内核因优先级继承
    而能将线程优先级
    提升到多高。
    默认值 -128 允许无限制。
    将其设置为等于或低于
    空闲线程优先级的
    优先级级别会禁用该功能。

线程在任何互斥锁相关
提升之前的优先级
在第一次被提升时
被保存在线程本身上，
且其持有的每个互斥锁
都在一个每线程列表中
被跟踪。每当更高
优先级线程等待
一个互斥锁，
内核就调整
持有线程的优先级。
当持有线程释放
一个锁（或高优先级
等待线程超时），
内核重新扫描
该线程剩余持有的
互斥锁，并从中
仍在其上等待的
最高优先级等待者
重新计算其优先级，
如果没有剩余
则回退到线程的
原始优先级。
无论持有的互斥锁
以何种顺序
被解锁，
这都给出正确结果。

如果互斥锁的持有者
本身被阻塞在
等待另一个互斥锁，
优先级提升
会沿该持有链
传播，
使每个阻塞
等待者进展的
线程依次
被提升，
直到
每次锁定
尝试所
行走的
链跳数
的实现
定义
上限。
超出
该上限
的持有者
保持
其提升
前的
优先级，
直到
后续
的锁定
尝试
再次
行走
该链。

实现
**************

定义互斥锁
==================

互斥锁使用 :c:struct:`k_mutex`
类型的变量来定义。
然后必须通过调用
:c:func:`k_mutex_init`
进行初始化。

下面的代码
定义并初始化
一个互斥锁。

.. code-block:: c

    struct k_mutex my_mutex;

    k_mutex_init(&my_mutex);

或者，
可以通过调用
:c:macro:`K_MUTEX_DEFINE`
在编译时
定义并初始化
一个互斥锁。

下面的代码
与上面代码段
效果相同。

.. code-block:: c

    K_MUTEX_DEFINE(my_mutex);

锁定互斥锁
===================

互斥锁
通过调用
:c:func:`k_mutex_lock`
来锁定。

下面的代码
基于上面的示例，
如果互斥锁
已被另一个线程
锁定，
则无限期
等待该互斥锁
变为可用。

.. code-block:: c

    k_mutex_lock(&my_mutex, K_FOREVER);

下面的代码
最多等待 100 毫秒
让互斥锁
变为可用，
如果互斥锁
没有变为可用
则给出警告。

.. code-block:: c

    if (k_mutex_lock(&my_mutex, K_MSEC(100)) == 0) {
        /* mutex successfully locked */
    } else {
        printf("Cannot lock XYZ display\n");
    }

解锁互斥锁
====================

互斥锁
通过调用
:c:func:`k_mutex_unlock`
来解锁。

下面的代码
基于上面的示例，
解锁之前
被线程锁定
的互斥锁。

.. code-block:: c

    k_mutex_unlock(&my_mutex);

建议用法
**************

使用互斥锁
为资源
（如物理
设备）
提供
独占
访问。

互斥原语，

无竞争的
操作仅

对共享
内存的
原子

:c:struct:`k_futex` 不是
内核对象，
不使用
内核对象
权限管理。
它们
驻留在
用户内存
中，
可被
任何
对该内存
具有
读写
访问的
线程
使用。
