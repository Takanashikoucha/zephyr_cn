最小堆数据结构
#############################

.. contents::
  :local:
  :depth: 2

最小堆（Min-Heap）实现提供了一种高效的数据结构，用于
管理动态变化的元素列表，同时保持快速提取最小值的能力。它是一种基于树的数据结构，
满足堆性质，支持常见操作，如向最小堆插入、删除和弹出最小元素

本节介绍该实现的动机、内部结构、API 用法，
以及面向嵌入式系统和实时环境的示例场景。

堆结构
**************

堆被维护为一个存储在数组中的完全二叉树。
每个节点满足**最小堆**性质：

    - 每个节点的值小于或等于其子节点的值。

该性质确保**最小元素始终位于根节点**
（索引 0）。

.. code-block:: text

    Index:      0   1   2   3   4   5   6
    Values:    [1,  3,  5,  8,  9, 10, 12]

                    1
                  /   \
                3       5
               / \     / \
              8   9  10  12

对于索引为 ``i`` 的任意节点，其子节点位于索引：

- 左子节点：:math:`2*i + 1`

- 右子节点：:math:`2*i + 2`

其父节点位于索引：

- 父节点：:math:`(i - 1) / 2`

使用场景
*********

MinHeap 适用于：

- 实现优先级队列
- 增量排序数据
- 资源仲裁（例如选择成本最低的资源）
- 协作式多任务系统中的调度
- 管理超时和延迟队列
- 基于优先级的传感器或数据采样

在 Zephyr 等 RTOS 环境中，该堆可用于内核级或
应用级模块，在这些模块中需要以最小延迟获取最高优先级资源。

值与引用变体
****************************

提供两种变体，区别仅在于元素的存储方式：

- ``min_heap``（如上所述）以**值**的形式将元素存储在连续
  缓冲区中。任意元素按内容（搜索）或按索引删除。
  这适合按内容查找的小型值优先级队列。

- ``min_heap_ref`` 存储**引用**到调用者拥有的节点，每个节点嵌入
  一个 ``min_heap_handle``。插入是零拷贝的，特定节点可
  使用调用者已持有的句柄以 :math:`O(\log n)` 复杂度删除，
  无需搜索。这适合按身份而非按内容删除的长生命周期对象，
  例如内核超时。

两者互为补充：值堆无法以优于 :math:`O(n)` 的复杂度
按身份删除，而引用堆不适合
按值加搜索的使用场景。``min_heap_ref`` 是纯头文件实现，
无需 Kconfig。
