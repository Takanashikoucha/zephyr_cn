Introduction
************

控制
pin
multiplexing
和
pin
configuration
parameters
如
pin
direction、
pull
up/down
resistors
等
的
hardware
blocks
被
命名
为
**pin
controllers**。
Pin
controller
的
main
users
是
SoC
hardware
peripherals
因为
controller
使
得
暴露
peripheral
signals
成为
可能
例如
将
``I2C0``
``SDA``
signal
map
到
pin
``PX0``。
不
仅
如此
它
通常
允许
配置
某些
对
peripheral
正确
functioning
必要
的
pin
settings
例如
根据
operating
frequency
的
slew
rate。
可用
的
configuration
options
是
vendor/SoC
特定
的
并
可以
从
简单
的
pull
up/down
options
到
更
advanced
的
settings
如
debouncing、
low
power
modes、
等
等。

Pin
control
在
hardware
中
的
实现
方式
是
vendor/SoC
特定
的。
通常
可以
找到
*centralized*
的
approach
即
所有
pin
configuration
parameters
由
单
个
hardware
block
（通常
命名
为
pinmux）
控制
包括
signal
mapping。
下面
的
figure
说明
这
个
approach。
``PX0``
可以
被
map
到
``UART0_TX``、
``I2C0_SCK``
或
``SPI0_MOSI``
取决于
``AF``
control
bits。
其他
configuration
parameters
如
pull
up/down
在
同一
block
中
通过
``CONFIG``
bits
控制。
这
个
model
被
多
个
SoC
families
使用
如
NXP
和
STM32
的
许多
SoC。

.. figure::
   images/hw-cent-control.svg

   示例
   将
   pin
   control
   集中
   到
   单
   个
   per
   pin
   block

其他
vendors/SoCs
使用
*distributed*
的
approach。
在
这样
的
情况
下
pin
mapping
和
configuration
由
多
个
hardware
blocks
控制。
下面
的
figure
说明
一
个
distributed
的
approach
其中
pin
mapping
由
peripherals
控制
如
在
Nordic
nRF
SoCs
中。
