.. _arm64_developer_guide:

ARM64
Developer
Guide
#####################

Wait
with
timeout
（WFxT）
************************

Arm
WFxT
extension
提供
WFET
和
WFIT
instructions，
它们
接受
一
个
绝对
virtual
counter
值
作为
timeout。
Zephyr
在
runtime
从
``ID_AA64ISAR2_EL1``
中
的
``WFxT``
field
检测
这
个
extension。
Arm64
architecture
代码
可以
用
``is_wfxt_implemented()``
查询
这
个
支持，
声明
在
:zephyr_file:`include/zephyr/arch/arm64/lib_helpers.h`。

当
Arm
architectural
timer
实现
:c:func:`arch_busy_wait`，
Arm64
path
用
WFET
用于
:c:func:`k_busy_wait`
如果
WFxT
被
实现。
它
从
``CNTVCT_EL0``
计算
一
个
deadline
并
重复
WFET
直到
counter
达到
那
个
deadline。
循环
是
必需
的
因为
WFET
被
允许
在
其
timeout
之前
返回。
没有
WFxT
的
CPUs
用
counter
polling
代替。
参考
:zephyr_file:`drivers/timer/arm_arch_timer.c`
获取
实现。

默认
的
Arm64
:c:func:`arch_cpu_idle`
实现
继续
使用
WFI。
与
Arm
architectural
timer
一起，
kernel
的
下次
timeout
被
编程
在
system
timer
中
并
其
interrupt
唤醒
CPU。
用
WFIT
替换
WFI
同时
保留
那
个
interrupt
不
移除
timer
编程
或
interrupt
处理。
避免
interrupt
需要
复杂
的
更改
到
kernel
timeout
accounting、
rescheduling
和
SMP
deadline
coordination，
添加
显著
的
风险
和
维护
成本
而
没有
展示
的
好处。

.. _arm64_mmu_dt_regions:

基于
Devicetree
的
MMU
Region
Mapping
************************************

在
ARM64
platforms
上
MMU
page
tables
可以
在
compile
time
自动
从
devicetree
填充。
任何
带
``compatible
=
"zephyr,memory-region"``
且
也
带
``zephyr,memory-attr``
property
的
node
将
被
architecture
startup
代码
转换
为
静态
的
``arm_mmu_region``
entry
—
不
需要
per-SoC
``mmu_regions.c``
更改。
