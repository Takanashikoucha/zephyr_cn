网络数据包处理统计
####################################

.. contents::
    :local:
    :depth: 2

本页介绍如何获取网络协议栈内部关于网络数据包处理统计的信息。

网络协议栈包含一套基础设施，用于确定网络数据包处理在发送路径或接收路径上分别花费多长时间。有两个 Kconfig 选项控制此功能。对于发送（TX）路径，该选项名为 :kconfig:option:`CONFIG_NET_PKT_TXTIME_STATS`；对于接收（RX）路径，该选项名为 :kconfig:option:`CONFIG_NET_PKT_RXTIME_STATS`。注意：对于 TX，会收集所有类型的网络数据包统计信息。对于 RX，仅收集 UDP、TCP 或原始（raw）数据包类型的网络数据包统计信息。

启用这些选项后，:ref:`net stats <net_shell>` 网络 shell 命令将显示如下信息：

.. code-block:: console

   Avg TX net_pkt (11484) time 67 us
   Avg RX net_pkt (11474) time 43 us

.. note::

   上述及下方的数值来自仿真 qemu_x86 单板及 UDP 流量

TX 时间表示从网络数据包创建到其被发送到网络所花费的时间。RX 时间表示从该数据包创建到其被传递给应用程序所花费的时间。数值单位为微秒。如果系统中定义了多个发送或接收队列，统计信息将按流量类别分别收集。这些队列由 :kconfig:option:`CONFIG_NET_TC_TX_COUNT` 和 :kconfig:option:`CONFIG_NET_TC_RX_COUNT` 选项控制。

如果启用 :kconfig:option:`CONFIG_NET_PKT_TXTIME_STATS_DETAIL` 或 :kconfig:option:`CONFIG_NET_PKT_RXTIME_STATS_DETAIL` 选项，则当网络数据包经过 IP 协议栈时，会为 TX 或 RX 网络数据包收集额外信息。

启用这些选项后，:ref:`net stats <net_shell>` 将显示如下信息：

.. code-block:: console

   Avg TX net_pkt (18902) time 63 us    [0->22->15->23=60 us]
   Avg RX net_pkt (18892) time 42 us    [0->9->6->11->13=39 us]

方括号内的数字包含网络数据包从上一状态过渡到下一状态所花费的微秒数信息。

在上述 TX 示例中，数值是对 **18902** 个数据包求得的平均值，包含以下信息：

* 数据包由应用程序创建，因此时间为 **0**。
* 数据包即将被放入发送队列。从网络数据包创建到该状态所花费的时间，在本示例中为 **22** 微秒。
* 正确的 TX 线程被调用，数据包从发送队列中读出。从上一状态起花费了 **15** 微秒。
* 网络数据包刚刚被发送，网络协议栈即将释放该网络数据包。从上一状态起花费了 **23** 微秒。
* 总计平均花费 **60** 微秒才将该网络数据包发送出去。数值 **63** 也表示相同的信息，但计算方式不同，因此由于舍入误差存在细微差异。

在上述 RX 示例中，数值是对 **18892** 个数据包求得的平均值，包含以下信息：

* 数据包由网络设备驱动程序创建，因此时间为 **0**。
* 数据包即将被放入接收队列。从网络数据包创建到该状态所花费的时间，在本示例中为 **9** 微秒。
* 正确的 RX 线程被调用，数据包从接收队列中读出。从上一状态起花费了 **6** 微秒。
* 随后网络数据包被处理并放入正确的套接字队列。从上一状态起花费了 **11** 微秒。
* 最后一个数值表示从那里到应用程序所花费的时间。此处该值为 **13** 微秒。
* 总计平均花费 **39** 微秒才将该网络数据包传递出去。数值 **42** 也表示相同的信息，但计算方式不同，因此由于舍入误差存在细微差异。
