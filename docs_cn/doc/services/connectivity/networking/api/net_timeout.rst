网络超时
###############

.. contents::
    :local:
    :depth: 2

概述
********

Zephyr 的网络基础设施主要使用毫秒分辨率的
运行时间（uptime）时钟来跟踪超时，
其中截止时间和时长均使用
32 位无符号值测量。32 位值在 49 天 17 小时 2 分钟
47.296 秒时回绕。

超时处理通常会受到延迟的影响，
因此检查超时的时间可能晚于其本应到期的时间。
要在不对最大延迟做任何任意假设的前提下正确处理
这一点，要求可直接表示的最大延迟
是一个 31 位非负数（``INT32_MAX``），
它在 24 天 20 小时 31 分钟 23.648
秒时溢出。

大多数网络超时短于该延迟回绕周期，
但少数协议允许以按秒计数的
32 位无符号值表示的延迟，
这相当于 42 位的毫秒计数。

net_timeout API 提供了一种通用超时机制，
用于正确跟踪这些长时长超时的
剩余时间。

使用
***

该 API 最简单的用法是：

#. 使用 :c:func:`net_timeout_set()` 配置一个网络超时。
#. 使用 :c:func:`net_timeout_evaluate()` 确定距离
   超时发生还有多久。安排一个在该延迟之后
   发生的超时。
#. 当超时回调被调用时，再次使用 :c:func:`net_timeout_evaluate()`
   判断超时是否已完成，还是仍有
   剩余时间。如果有剩余时间，重新安排回调。
#. 在超时运行期间，使用 :c:func:`net_timeout_remaining` 获取
   距离超时可用的秒数。这可用于
   显式更新超时，做法应是取消任何
   挂起的回调，并使用新超时从第 1 步重新开始。

:c:struct:`net_timeout` 包含一个 ``sys_snode_t``，允许
多个超时实例聚合起来共享单个内核定时器元素。
应用必须对所有实例使用 :c:func:`net_timeout_evaluate()`
来确定下一个要发生的超时事件。

:c:func:`net_timeout_deadline()` 可用于重建超时的
全精度截止时间。它主要用于测试，
但在某些应用中可能有用，
因为它允许以毫秒分辨率计算
剩余时间。
