.. _mcumgr_smp_protocol_specification:

SMP 协议规范
##########################

本文描述简单管理协议（SMP，Simple Management Protocol）。MCUmgr 使用 SMP 向设备传递请求并接收响应。

SMP 是应用层协议。本文档不涉及其底层的传输层。

.. note::
    此处提到的 SMP 指 MCUmgr 的 SMP（Simple Management Protocol），
    与 Bluetooth 中的 SMP（Security Manager Protocol）无关，
    但存在用于 Bluetooth 的 MCUmgr SMP 传输。

帧：信封
*******************

每个帧由头部和数据组成。如果底层传输层支持分片，
头部的 ``Data Length`` 字段可用于重组。
字段长度超过一个字节时，帧按"Big Endian"（网络字节序）编码，
形式如下：

.. _mcumgr_smp_protocol_frame:

.. table::
    :align: center

    +-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
    |3              |2              |1              |0              |
    +-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
    |7|6|5|4|3|2|1|0|7|6|5|4|3|2|1|0|7|6|5|4|3|2|1|0|7|6|5|4|3|2|1|0|
    +-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
    | Res |Ver| OP  |      Flags    |          Data Length          |
    +-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
    |            Group ID           | Sequence Num  |   Command ID  |
    +-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
    |                             Data                              |
    |                             ...                               |
    +-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+

.. note::
    原始规范指出 SMP 应支持接收"Little-endian"和"Big-endian"两种帧，
    但实际上 MCUmgr 库被硬编码为始终将"Network"侧视为"Big-endian"。


数据是可选的，``Data Length`` 为零时不存在数据。
数据的编码取决于目标组/ID。

各字段及其含义说明如下：

.. table::
    :align: center

    +-------------------+---------------------------------------------------+
    | 字段               | 描述                                               |
    +===================+===================================================+
    | ``Res``           | 保留的未使用字段，必须始终置 0。                  |
    +-------------------+---------------------------------------------------+
    | ``Ver`` (Version) | 表示所使用的协议版本。应置为 0b01 以使用较新的  |
    |                   | SMP 传输（错误码更详细，且通过映射返回），      |
    |                   | 否则保持 0b00 以使用旧版 SMP 协议。版本 0b10 和 |
    |                   | 0b11 保留供将来使用，不应使用。                |
    +-------------------+---------------------------------------------------+
    | ``OP``            | :c:enum:`mcumgr_op_t`，决定信息是写入设备还是   |
    |                   | 从设备读取，以及数据包包含的是发往 SMP 服务器的 |
    |                   | 请求还是来自服务器的响应。                     |
    +-------------------+---------------------------------------------------+
    | ``Flags``         | 保留用于标志位；目前尚未定义任何标志，          |
    |                   | 该字段应置为 0。                                 |
    +-------------------+---------------------------------------------------+
    | ``Data Length``   | ``Data`` 字段的长度。                            |
    +-------------------+---------------------------------------------------+
    | ``Group ID``      | :c:enum:`mcumgr_group_t`，详见                 |
    |                   | :ref:`mcumgr_smp_protocol_group_ids`。         |
    +-------------------+---------------------------------------------------+
    | ``Sequence Num``  | 帧序列号。每个请求帧使该编号加一。             |
    |                   | 响应的 Sequence Num 应与请求中的保持一致。     |
    +-------------------+---------------------------------------------------+
    | ``Command ID``    | ``Group`` 内的命令。                             |
    +-------------------+---------------------------------------------------+
    | ``Data``          | 大小为 ``Data Length`` 的数据载荷。它是可选的， |
    |                   | 因为 ``Data Length`` 可置为零，表示头部之后     |
    |                   | 没有数据。                                     |
    +-------------------+---------------------------------------------------+

.. note::
    ``Data`` 的内容取决于 ``OP``、``Group ID`` 和 ``Command ID`` 的值。

管理 ``Group ID``
=========================

SMP 协议支持预定义的常用组，并允许用户自定义组。
下表列出了常用组：


.. table::
    :align: center

    +---------------+-----------------------------------------------+
    | 十进制 ID     | 组描述                                        |
    +===============+===============================================+
    | ``0``         | :ref:`mcumgr_smp_group_0`                     |
    +---------------+-----------------------------------------------+
    | ``1``         | :ref:`mcumgr_smp_group_1`                     |
    +---------------+-----------------------------------------------+
    | ``2``         | :ref:`mcumgr_smp_group_2`                     |
    +---------------+-----------------------------------------------+
    | ``3``         | :ref:`mcumgr_smp_group_3`                     |
    +---------------+-----------------------------------------------+
    | ``4``         | 应用/系统日志管理                             |
    |               | （Zephyr 当前未使用）                         |
    +---------------+-----------------------------------------------+
    | ``5``         | 运行时测试（Run-time tests）                  |
    |               | （Zephyr 未使用）                             |
    +---------------+-----------------------------------------------+
    | ``6``         | 分割镜像管理（Split image management）        |
    |               | （Zephyr 未使用）                             |
    +---------------+-----------------------------------------------+
    | ``7``         | 崩溃测试应用（Test crashing application）     |
    |               | （Zephyr 未使用）                             |
    +---------------+-----------------------------------------------+
    | ``8``         | :ref:`mcumgr_smp_group_8`                     |
    +---------------+-----------------------------------------------+
    | ``9``         | :ref:`mcumgr_smp_group_9`                     |
    +---------------+-----------------------------------------------+
    | ``63``        | :ref:`mcumgr_smp_group_63`                    |
    +---------------+-----------------------------------------------+
    | ``64``        | 定义应用特定管理组的基础组。                  |
    +---------------+-----------------------------------------------+

上述各组的载荷（用户组（``64`` 及以上）除外）始终采用
CBOR 编码。``64`` 及以上的组可以自行定义
数据通信方案。

最小响应
****************

无论发出什么命令，只要请求的另一端存在 SMP 客户端，
就应发出包含头部和 CBOR 映射容器的响应。
仅当不存在 SMP 服务或设备无响应时，才允许没有响应。

最小响应的 SMP 数据
=========================

最小响应为：

.. tabs::

   .. group-tab:: SMP version 2

      .. code-block:: none

          {
              (str)"err" : {
                  (str)"group"    : (uint)
                  (str)"rc"       : (uint)
              }
          }

   .. group-tab:: SMP version 1 (and non-group SMP version 2)

      .. code-block:: none

          {
              (str)"rc"       : (int)
          }

其中：

.. table::
    :align: center

    +------------------+-------------------------------------------------------------------------+
    | "err" -> "group" | :c:enum:`mcumgr_group_t` 基于组的错误码所属的组。仅在使用 SMP version 2  |
    |                  | 且返回错误时出现。                                                       |
    +------------------+-------------------------------------------------------------------------+
    | "err" -> "rc"    | 包含基于组的错误码的索引。仅在使用 SMP version 2 且非零（出错状态）时    |
    |                  | 出现。                                                                   |
    +------------------+-------------------------------------------------------------------------+
    | "rc"             | :c:enum:`mcumgr_err_t` 仅在使用 SMP version 1 且非零（出错状态）时出现， |
    |                  | 或在使用 SMP version 2 且为 SMP 错误时出现。                             |
    +------------------+-------------------------------------------------------------------------+

注意，在命令成功的情况下将返回一个空映射（``rc``/``err`` 仅在出错状态时
才返回，因此如果仅返回空映射或响应中缺少这些字段，即可认为请求成功。
对于 SMP version 2，与 SMP 本身相关、且不属于特定组的错误仍将以 ``rc``
错误形式返回，因此 SMP version 2 客户端必须能够同时处理这两种类型的错误。
