.. _formatted_output:

格式化输出
################

应用以及 Zephyr 本身都需要用于格式化数值供用户查看的基础设施。
标准 C99 库的 ``*printf()`` 功能可满足流式输出设备或内存
缓冲区的需求，但在嵌入式系统中，设备可能不接受流式数据，
也可能没有内存来存储格式化后的输出。

Zephyr 内部 API 传统上同时为
:c:func:`printk` 和 Zephyr 内部的最小 libc 提供该功能，但使用
各自独立的内部接口。日志、跟踪、shell 以及其他
应用根据构建选项使用这些 API 或标准 libc 例程。

:c:func:`cbprintf` 公开 API 将 C99 格式字符串和
参数进行转换，通过回调机制逐字符产生输出，
取代了原有的内部函数，并支持几乎所有 C99 格式说明符。
Zephyr 中对 ``s*printf()`` C 库的现有用法可以转换为
:c:func:`snprintfcb()`，以避免引入 libc 实现。

多个 Kconfig 选项控制所启用功能的集合，
从而对功能和内存使用进行一定控制：

* :kconfig:option:`CONFIG_CBPRINTF_FULL_INTEGRAL`
  或 :kconfig:option:`CONFIG_CBPRINTF_REDUCED_INTEGRAL`
* :kconfig:option:`CONFIG_CBPRINTF_FP_SUPPORT`
* :kconfig:option:`CONFIG_CBPRINTF_FP_A_SUPPORT`
* :kconfig:option:`CONFIG_CBPRINTF_FP_ALWAYS_A`
* :kconfig:option:`CONFIG_CBPRINTF_N_SPECIFIER`

:kconfig:option:`CONFIG_CBPRINTF_LIBC_SUBSTS` 可用于提供行为类似
标准 libc 函数、但使用所选 cbprintf
格式化器而非从 libc 引入另一个格式化器的函数。

此外，:kconfig:option:`CONFIG_CBPRINTF_NANO` 可用于回退到
在添加该功能之前用于 :c:func:`printk` 的
极其节省空间但功能有限的格式化器。

.. _cbprintf_packaging:

Cbprintf 打包
******************

通常，调用 ``printf``
族的函数时会同步格式化字符串。然而，在某些情况下，延迟
格式化是有利的。在这种情况下，必须捕获状态（格式字符串和参数）。
这样的状态构成一个自包含的包，其中包含格式字符串和
参数。此外，包可以包含格式字符串的一部分（格式字符串或任何 ``%s`` 参数）的字符串
副本。包的主要内容类似于 va_list 栈帧，因此
使用标准格式化函数处理包。由于包包含按
va_list 帧处理的数据，必须保持严格对齐。由于所需的填充，
包的大小取决于对齐方式。复制包时，应
将其复制到与源具有相同对齐方式的内存块中。

包可以有以下几种变体：

* **Self-contained（自包含）** - 将非只读字符串附加到包中。只要可以访问
  只读字符串位置，就可以从这样的包格式化字符串。包可以包含
  只读字符串在包内位置的信息。该信息可用于将包转换为
  完全自包含的包。
* **Fully self-contained（完全自包含）** - 所有字符串都附加到包中。无需任何
  外部数据即可从这样的包格式化字符串。
* **Transient（临时）** - 仅存储参数。包包含
  非只读字符串指针在包内位置的信息。可选地，
  它还可以包含只读字符串位置信息。只要非只读
  字符串仍然有效且只读
  字符串可访问，就可以从这样的包格式化字符串。或者，如果包中包含只读字符串
  位置信息，可以将包转换为 **self-contained**
  包或 **fully self-contained** 包。

可以通过两种方法创建包：

* 运行时 - 使用 :c:func:`cbprintf_package` 或 :c:func:`cbvprintf_package`。该方法
  扫描格式字符串，并根据检测到的格式说明符构建
  包。
* 静态 - 参数类型在编译时由预处理器检测，
  包作为对提供内存的简单赋值创建。该方法
  比运行时方法快得多（超过 15 倍），但存在
  一个显著限制：当使用 char 指针时，无法区分 ``%p`` 和 ``%s``。它将所有（无符号）char 指针视为 ``%s``，因此会尝试
  将字符串附加到包中。在从 **transient** 包转换为 **self-contained** 包时，使用
  :c:macro:`CBPRINTF_PACKAGE_CONVERT_PTR_CHECK` 标志可以正确处理该问题。然而，这需要
  访问格式字符串，而这并不总是可行的，因此建议
  将用于 ``%p`` 的 char 指针转换为 ``void *``。当使用
  :c:macro:`CBPRINTF_PACKAGE_CONVERT_PTR_CHECK` 标志调用 :c:func:`cbprintf_package_convert` 时，
  若 char 指针与
  ``%p`` 一起使用，会生成一条日志警告。


多个 Kconfig 选项控制打包的行为：

* :kconfig:option:`CONFIG_CBPRINTF_PACKAGE_LONGDOUBLE`
* :kconfig:option:`CONFIG_CBPRINTF_STATIC_PACKAGE_CHECK_ALIGNMENT`

Cbprintf 包转换
===========================

可以将包转换为包含更多信息的变体，例如
**transient** 包可以转换为 **self-contained**。如果创建包时使用了
:c:macro:`CBPRINTF_PACKAGE_ADD_RO_STR_POS`
标志，则可以转换为 **fully self-contained** 包。

:c:func:`cbprintf_package_copy` 用于计算新包所需的空间
并复制和转换包。

Cbprintf 包格式
======================

包格式包含平台相关的填充。包由头部组成，
其中包含包的大小（不含附加字符串）以及
附加字符串的数量。其后是参数，包含对齐填充，
类似于 *va_list* 栈帧。再其后是与字符串使用的字符
指针参数相关的数据，这些字符串未附加到包中（但之后
可能由 :c:func:`cbprinf_package_convert` 附加）。最后，包可选地
包含附加字符串。每个字符串包含 1 字节头部，其中包含
存储地址参数的位置索引。打包时地址被置为
空，字符串格式化之前更新为指向包内当前字符串
位置。更新地址参数必须在字符串
格式化之前进行，因为每次复制包时地址都会变化。

+------------------+-------------------------------------------------------------------------+
| 头部           | 1 字节：参数列表大小，含头部和 *fmt*（以 32 位字为单位） |
|                  +-------------------------------------------------------------------------+
| sizeof(void \*)  | 1 字节：附加到包的字符串数量                       |
|                  +-------------------------------------------------------------------------+
|                  | 1 字节：只读字符串参数位置数量                   |
|                  +-------------------------------------------------------------------------+
|                  | 1 字节：临时字符串参数位置数量                   |
|                  +-------------------------------------------------------------------------+
|                  | 平台相关填充，至 sizeof(void \*)                            |
+------------------+-------------------------------------------------------------------------+
| 参数        | 指向 *fmt* 的指针（若 *fmt* 附加到包中则为空）          |
|                  +-------------------------------------------------------------------------+
|                  | （平台特定对齐的可选填充）                      |
|                  +-------------------------------------------------------------------------+
|                  | argument 0                                                              |
|                  +-------------------------------------------------------------------------+
|                  | （平台特定对齐的可选填充）                      |
|                  +-------------------------------------------------------------------------+
|                  | argument 1                                                              |
|                  +-------------------------------------------------------------------------+
|                  | ...                                                                     |
+------------------+-------------------------------------------------------------------------+
| 字符串位置  | 包内只读字符串所在位置的字的索引 |
| 信息      +-------------------------------------------------------------------------+
| （可选）       | 临时字符串所在位置的参数索引与参数位置索引对     |
|                  |                                                     |
+------------------+-------------------------------------------------------------------------+
| 附加         | 1 字节：包内关联参数位置的索引 |
| 字符串          +-------------------------------------------------------------------------+
| （可选）       | 以空字符结尾的字符串                                                  |
|                  +-------------------------------------------------------------------------+
|                  | ...                                                                     |
+------------------+-------------------------------------------------------------------------+

.. warning::

  如果同时选择了 :kconfig:option:`CONFIG_MINIMAL_LIBC` 和
  :kconfig:option:`CONFIG_CBPRINTF_NANO`，使用 C 标准库
  函数（如 ``printf`` 或 ``snprintf``）进行格式化的功能将受到限制。 除其他
  限制外，``%n`` 说明符、大多数格式标志、精度控制以及
  浮点数均不受支持。

.. _cbprintf_packaging_limitations:

限制与建议
===============================

* 建议将与 ``%p`` 格式说明符一起使用的任何字符指针
  转换为其他指针类型（例如 ``void *``）。如果无法访问格式字符串，则只能
  使用静态打包，它会附加所有检测到的字符串。用于
  ``%p`` 的字符指针将被视为字符串指针。从意外位置
  复制可能带来严重后果（例如，内存错误或安全违规）。
