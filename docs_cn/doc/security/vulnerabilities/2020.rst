UpdateHub 可能解引用未初始化的指针

在 updatehub_probe 中，JSON 解析完成后，立即在两处从输出结构体中
访问 objects\[1]。如果 JSON 中的元素少于两个，此访问将引用
未初始化的栈内存。这可能导致崩溃、拒绝服务，甚至可能泄露信息。

建议在修复可用之前禁用 updatehub。

参见 NCC-ZEP-030

:cve:`2020-10062`
-----------------

MQTT 中的数据包长度解码错误

CVE：Zephyr 项目 MQTT 数据包长度解码器中的一处差一错误可能导致
内存损坏和可能的远程代码执行。NCC-ZEP-031

MQTT 数据包头长度可为 1 到 4 字节。代码中的差一错误可能使其被
解释为 5 字节，从而导致整数溢出，进而引发内存损坏。

此问题已在 v2.3 的 main 分支中修复。

- `Zephyr 项目缺陷跟踪器 ZEPSEC-84
  <https://zephyrprojectsec.atlassian.net/browse/ZEPSEC-84>`_

- `commit 11b7a37d 针对 v2.3
  <https://github.com/zephyrproject-rtos/zephyr/pull/23821/commits/11b7a37d9a0b438270421b224221d91929843de4>`_

- `NCC-ZEP 报告`_（NCC-ZEP-031）

:cve:`2020-13603`
-----------------

mempool 中可能的溢出

 * Zephyr 提供预构建的 'malloc' 包装函数作为替代。
 * 'malloc' 函数是 'sys_mem_pool_alloc' 函数的包装
 * sys_mem_pool_alloc 以不安全的方式分配 'size + WB_UP(sizeof(struct sys_mem_poolBlock))'。
 * 请求非常大的 size 值会导致内部整数回绕。
 * 整数回绕导致成功分配非常小的内存。
 * 例如：调用 malloc(0xffffffff) 导致成功分配 7 字节。
 * 这会导致堆溢出。
