Zephyr
3.1.0
############

以下
sections
provide
detailed
的
lists
of
changes
by
component。

API
Changes
***********

Changes
in
this
release
=======================

*
所有
Zephyr
的
public
headers
被
moved
到
``include/zephyr``
meaning
它们
在
included
时
需要
被
prefixed
with
``<zephyr/...>``。
因为
这
个
change
可以
potentially
break
many
的
applications
或
libraries
:kconfig:option:`CONFIG_LEGACY_INCLUDE_PATH`
被
provided
用于
allow
use
old
的
include
path。
这
个
option
now
被
enabled
by
default
用于
allow
一
个
smooth
的
transition。
在
order
to
facilitate
migration
到
new
的
include
prefix
一
个
script
用于
automate
这
个
process
也
被
provided:
:zephyr_file:`scripts/utils/migrate_includes.py`。

*
LoRaWAN:
:c:func:`lorawan_send`
中
的
message
type
parameter
被
changed
from
``uint8_t``
to
``enum
lorawan_message_type``。
如果
``0``
被
passed
for
unconfirmed
message
这
必须
被
changed
to
``LORAWAN_MSG_UNCONFIRMED``。
*
Bluetooth:
Applications
where
:kconfig:option:`CONFIG_BT_EATT`
is
enabled
必须
set
:c:member:`chan_opt`
field
on
the
GATT
parameter
structs。
要
keep
old
的
behavior
use
:c:enumerator:`BT_ATT_CHAN_OPT_NONE`。

*
Disk
Subsystem:
SPI
mode
的
SD
cards
now
use
the
SD
subsystem
用于
communicate
with
SD
cards。
See
:ref:`the
disk
access
api
<disk_access_api>`
获取
new
的
devicetree
binding
format
required
的
example。

*
Kconfig
preprocessor
function
``dt_nodelabel_has_compat``
被
redefined
用于
consistency
with
the
``dt_nodelabel_has_prop``
function
和
devicetree
macros
like
:c:func:`DT_NODE_HAS_COMPAT`。
Now
该
function
不
take
into
account
the
status
of
the
checked
node。
Its
former
functionality
被
newly
introduced
的
``dt_nodelabel_enabled_with_compat``
function
provided。
