ICMsg
with
dynamically
allocated
buffers
backend
################################################

通过
这
个
backend
transferred
的
data
在
shared
memory
上
dynamically
allocated
的
buffers
中
travel。
Allocation
是
thread
safe
的
并
可以
从
任何
context
发生。
Backend
support：

*
Multiple
endpoints。
*
No
copy
的
sending。
*
Holding
RX
buffers。
*
从
interrupt
context
sending。
*
Two
levels
的
endpoint
priorities。
*
Statistics
和
optional
的
shell
command
带
utilization
report
*
Up
to
32
blocks
被
supported。
*
Data
cache
support。
*
Low
的
memory
footprint
（about
2
kB
的
code）。

Overview
========

对
每个
direction
一
个
shared
memory
region
被
reserved
且
每个
region
被
divided
到
两
个
parts。
一
个
part
form
一
个
fixed
size
buffers
的
pool
且
allocator
从
pool
中
adjacent
的
buffers
build
一
个
variable
size
的
buffer。
另
一
个
part
被
used
用于
control
path
consist
of
两
个
message
queues
（对
每个
direction）。
有
一
个
producer
queue
它
被
sender
written
且
被
receiver
read
还有
一
个
consumer
queue
它
被
receiver
written
且
被
sender
read。
Producer
queue
有
关于
next
message
的
location
（在
pool
内）
的
information。
Consumer
queue
有
关于
consumed
message
的
location
（在
pool
内）
的
information。

Data
sending
的
process
是
以下
的：

*
Sender
从
pool
allocate
一
个
或
多
个
blocks。
如果
没有
足够
的
sequential
blocks
一
个
thread
context
用
provided
的
timeout
wait
它
也
包括
K_FOREVER
和
K_NO_WAIT。
*
Allocated
的
blocks
被
filled
with
data。
在
first
block
的
beginning
有
一
个
32
bit
的
message
header
带
length、
endpoint
ID
和
own
block
index。
对
zero
copy
的
case
这
由
caller
done
否则
它
被
automatically
copied。
在
这
期间
其他
threads
在
有
足够
的
free
blocks
给
它们
的
情况
下
不
被
任何
方式
blocked。
它们
可以
allocate、
send
data
和
receive
data。
*
带
message
beginning
的
block
index
被
written
到
producer
queue。
Endpoint
的
priority
的
information
被
appended
到
block
index。
