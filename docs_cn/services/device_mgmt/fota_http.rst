Firmware
Over
the
Air
over
HTTP
###############################

Overview
********

FOTA
HTTP
library
从
HTTP
server
download
一
个
firmware
image
并
straight
write
它
到
当前
不
在
run
的
MCUboot
slot。
它
然后
让
application
request
swap、
confirm
新
的
image
或
erase
slot。
与
:ref:`hawkBit
or
UpdateHub
<ota>`
不同
没有
device
management
protocol
involved：
任何
能
serve
file
的
web
server
都
可以
act
作为
update
source
这
使
它
suitable
用于
simple
的
deployments
和
bench
testing。

Image
在
arrive
时
通过
:ref:`flash_img_api`
streamed
到
flash
所以
它
的
size
不
被
RAM
limited。
Slot
在
write
期间
被
progressively
erased
并
slot
的
MCUboot
trailer
在
first
byte
land
之前
被
cleared
所以
previous
image
的
leftover
永远
不
会
被
mistaken
作为
pending
的
swap。

在
download
后
library
从
flash
read
回
MCUboot
header
并
在
data
不
是
image
时
fail
带
``-ENOEXEC``。
它
不
verify
signature：
MCUboot
在
image
被
booted
之前
做
这
个
并
那
个
check
decide
image
是否
run。
Optional
的
SHA-256
comparison
与
caller
supplied
的
digest
在
:kconfig:option:`CONFIG_FOTA_HTTP_SHA256_CHECK`
下
available
用于
在
reboot
之前
catch
corrupted
的
transfer。
被
那
个
comparison
或
下面
的
downgrade
check
rejected
的
image
从
slot
被
erased。
在
part
way
failed
的
download
后
:c:func:`fota_http_apply`
refuse
slot
直到
另
一
个
download
到
它
成功
同时
partial
的
data
保持
在
place
用于
resume。

cycle

sequence
