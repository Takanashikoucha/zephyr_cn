.. _mcumgr_smp_transport_ble:

Bluetooth
Low
Energy
（LE）
*************************

MCUmgr
Clients
在
implement
SMP
client
时
需要
use
以下
Bluetooth
Characteristics：

-
**Service
UUID**：
``8D53DC1D-1DB7-4CD3-868B-8A527460AA84``
-
**Characteristic
UUID**：
``DA2E7828-FBCE-4E01-AE9E-261174997C48``

所有
的
SMP
communication
use
单
个
GATT
characteristic。
SMP
request
通过
GATT
Write
Without
Response
command
sent。
SMP
response
以
GATT
Notification
的
form
sent。

如果
SMP
request
或
response
太
large
无法
fit
在
单
个
GATT
command
中
sender
将
它
fragment
到
多
个
packets
中。
当
request
或
response
被
fragmented
时
不
introduce
additional
的
framing
payload
只
被
split
到
多
个
packets
中。
因为
GATT
guarantee
packets
的
ordered
delivery
first
fragment
中
的
SMP
header
contain
sufficient
的
information
用于
reassembly。

.. _mcumgr_smp_transport_uart:

UART/serial
and
console
***********************

Zephyr
MCUmgr
subsystem
的
SMP
protocol
specification
use
basic
的
framing
of
data
用于
allow
UART
channel
的
multiplexing。
Multiplexing
require
用
两
个
byte
的
marker
prefix
每个
frame
并
用
newline
terminate
它。
当前
MCUmgr
impose
一
个
127
byte
的
limit
在
frame
size
上
虽然
没有
real
的
protocol
constraints
require
这
个
limit。
