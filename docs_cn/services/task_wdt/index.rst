Task
Watchdog
#############

Overview
********

Many
microcontrollers
feature
一
个
hardware
的
watchdog
timer
peripheral。
它
的
purpose
是
在
severe
的
software
malfunctions
的
case
中
trigger
一
个
action
（usually
一
个
system
reset）。
一
旦
initialized
watchdog
timer
必须
在
regular
的
intervals
被
restarted
（"fed"）
prevent
它
从
timing
out。
如果
software
got
stuck
且
不
能
再
manage
feed
watchdog
corrective
的
action
被
triggered
用于
将
system
bring
back
到
normal
的
operation。

在
real
time
的
operating
systems
中
multiple
tasks
run
in
parallel
single
的
watchdog
instance
可能
不
再
sufficient
因为
它
只
可以
被
used
用于
一
个
task。
这
个
基于
kernel
timers
的
software
watchdog
provide
一
种
method
用于
supervise
multiple
threads
或
tasks
（called
watchdog
channels）。

Existing
的
hardware
watchdog
可以
被
used
作为
optional
的
fallback
如果
task
watchdog
自己
或
scheduler
有
malfunction。

Task
watchdog
use
一
个
kernel
timer
作为
它
的
backend。
如果
properly
configured
timer
ISR
在
normal
的
operation
期间
never
actually
被
called
因为
timer
在
feed
calls
中
continuously
被
updated。

当前
不
可以
have
multiple
的
instances
of
task
watchdogs。
Instead
task
watchdog
API
可以
globally
被
accessed
用于
add
或
delete
new
的
channels
而
不
在
firmware
中
passing
around
一
个
context
或
device
pointer。

Maximum
数量
的
channels
被
predefined
via
Kconfig
且
应该
被
adjusted
以
match
exactly
application
required
的
channels
数量。

Configuration
Options
*********************

Related
的
configuration
options
可以
found
在
:zephyr_file:`subsys/task_wdt/Kconfig`
下。
