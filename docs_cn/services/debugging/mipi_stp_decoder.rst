MIPI
STP
Decoder
################

MIPI
System
Trace
Protocol
（MIPI
STP）
被
developed
作为
一
个
generic
的
base
protocol
它
可以
被
多
个
application
specific
的
trace
protocols
shared。
它
作为
一
个
wrapper
protocol
serve
它
merge
disparate
的
streams
它们
通常
contain
来自
不同
trace
sources
的
不同
trace
protocols。
Stream
consist
of
opcode
（shortest
是
4
bit
长）
后
跟
optional
的
data
和
optional
的
timestamp。
有
opcodes
用于
data
（8、
16、
32、
64
bit
data
marked/not
marked、
带
或
不
带
timestamp）、
stream
recognition
（master
和
channel）、
synchronization
（ASYNC
opcode）
和
其他。

一
个
protocol
被
used
的
example
是
ARM
Coresight
STM
（System
Trace
Macrocell）
那里
written
到
Stimulus
Port
registers
的
data
directly
map
到
STP
stream。

这
个
module
可
被
used
用于
perform
data
stream
的
on
chip
decoding。
STP
v2
被
used。

Usage
*****

Decoder
用
一
个
callback
initialized。
Callback
在
每个
decoded
的
opcode
上
被
called。
Decoder
有
internal
state
因为
opcodes
之间
有
dependencies
（例如
timestamp
可以
relative）。
Decoder
可以
在
synchronization
中
或
不
在。
Initial
state
可
configurable。
如果
decoder
不
synchronized
到
stream
它
decode
每个
nibble
search
ASYNC
opcode。
Loss
of
synchronization
可以
通过
call
:c:func:`mipi_stp_decoder_sync_loss`
被
indicated
到
decoder。
:c:func:`mipi_stp_decoder_decode`
被
used
用于
decode
data。

Limitations
***********

有
以下
limitations：

*
Decoder
只
support
little
endian
的
architectures。
*
当
decoding
nibbles
时
core
support
unaligned
memory
access
时
更
efficient。
Implementation
support
一
个
optimized
的
version
带
unaligned
memory
access
和
一
个
generic
的。
Optimized
的
version
被
used
用于
ARM
Cortex
M
（M0
除外）。
*
Limited
的
set
的
most
common
的
opcodes
被
implemented。
