Connection
Management
#####################

Zephyr
Bluetooth
stack
使用
一
个
称为
:c:struct:`bt_conn`
的
abstraction
代表
到
其他
devices
的
connections。
这
个
struct
的
internals
不
被
暴露
给
application
但
有限
的
information
（如
remote
address）
可以
用
:c:func:`bt_conn_get_info`
API
获取。
Connection
objects
是
reference
counted
的
application
预期
在
存储
connection
pointer
更
长
时间
时
使用
:c:func:`bt_conn_ref`
API
因为
这
确保
object
保持
valid
（即使
connection
被
disconnected）。
类似
地
:c:func:`bt_conn_unref`
API
在
释放
对
connection
的
reference
时
使用。

一
个
common
的
mistake
是
忘记
unrelease
由
functions
:c:func:`bt_conn_le_create`
和
:c:func:`bt_conn_le_create_synced`
创建
的
connection
object
的
reference。
为
保护
防止
这
个
使用
:kconfig:option:`CONFIG_BT_CONN_CHECK_NULL_BEFORE_CREATE`
Kconfig
option
它
强制
这些
functions
在
传递
给
它们
的
connection
pointer
不
是
NULL
时
返回
error。
这
帮助
spot
这样
的
issues
并
避免
由
不
release
connection
object
导致
的
sporadic
bugs。

应用
可以
通过
用
:c:func:`bt_conn_cb_register`
或
:c:macro:`BT_CONN_CB_DEFINE`
APIs
注册
一
个
:c:struct:`bt_conn_cb`
struct
跟踪
connections。
这
个
struct
让
application
定义
callbacks
用于
connection
&
disconnection
events
以及
其他
与
connection
相关
的
events
如
security
level
的
变化
或
connection
parameters
的
变化。
当
作为
central
时
application
也
将
通过
:c:func:`bt_conn_le_create`
API
的
return
value
获取
connection
object。
