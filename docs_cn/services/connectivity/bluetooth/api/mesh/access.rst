Access
layer
############

Access
layer
是
application
到
Bluetooth
Mesh
network
的
interface。
Access
layer
提供
mechanisms
将
node
行为
compartmentalize
到
elements
和
models
它们
由
application
实现。

Mesh
models
***********

Mesh
node
的
functionality
由
models
代表。
一
个
model
实现
node
支持
的
单
个
behavior
如
作为
一
个
light、
一
个
sensor
或
一
个
thermostat。
Mesh
models
被
分组
到
*elements*。
每个
element
被
分配
自己
的
unicast
address
并
只
能
包含
每
种
type
的
model
一
个。
传统
上
每个
element
代表
mesh
node
行为
的
单
个
aspect。
例如
包含
一
个
sensor、
两
个
lights
和
一
个
power
outlet
的
node
将
这
些
functionality
分散
到
四
个
elements
每个
element
实例化
支持
行为
单
个
aspect
所需
的
所有
models。

Node
的
element
和
model
structure
在
node
composition
data
中
specified
它
在
initialization
时
传递
给
:c:func:`bt_mesh_init`。
Bluetooth
SIG
定义
了
一
组
foundation
models
（参考
:ref:`bluetooth_mesh_models`）
和
一
组
用于
实现
common
behavior
的
models
在
`Bluetooth
Mesh
Model
Specification
<https://www.bluetooth.com/specifications/mesh-specifications/>`_
中。
所有
不
由
Bluetooth
SIG
specified
的
models
都是
vendor
models
必须
绑定
到
一
个
Company
ID。

Mesh
models
有
多
个
parameters
可以
通过
mesh
stack
的
initialization
或
:ref:`bluetooth_mesh_models_cfg_srv`
配置：

Opcode
list
===========

Opcode
list
包含
model
可以
接收
的
所有
message
opcodes
以及
最小
可
接受
的
payload
length
和
传递
它们
的
callback。
