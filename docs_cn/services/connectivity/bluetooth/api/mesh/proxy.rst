Proxy
#####

Proxy
feature
允许
phones
等
legacy
devices
通过
GATT
access
Bluetooth
Mesh
network。
Proxy
feature
只
在
设置
:kconfig:option:`CONFIG_BT_MESH_GATT_PROXY`
option
时
被
compiled
in。
Proxy
feature
state
由
:ref:`bluetooth_mesh_models_cfg_srv`
控制
initial
value
可以
用
:c:member:`bt_mesh_cfg_srv.gatt_proxy`
set。

启用
Proxy
feature
的
Nodes
可以
advertise
带
Network
Identity
和
Node
Identity
由
:ref:`bluetooth_mesh_models_cfg_cli`
控制。

GATT
Proxy
state
indicate
Proxy
feature
是否
被
supported。

Private
Proxy
*************

支持
Proxy
feature
和
:ref:`bluetooth_mesh_models_priv_beacon_srv`
model
的
node
可以
advertise
带
Private
Network
Identity
和
Private
Node
Identity
types
由
:ref:`bluetooth_mesh_models_priv_beacon_cli`
控制。
通过
advertise
这
组
identification
types
node
允许
legacy
device
通过
GATT
connect
到
network
同时
maintain
network
的
privacy。

Private
GATT
Proxy
state
indicate
Private
Proxy
functionality
是否
被
supported。

Proxy
Solicitation
******************

在
node
上
GATT
Proxy
和
Private
GATT
Proxy
states
都
被
disabled
的
情况
下
legacy
device
无法
connect
到
它。
支持
:ref:`bluetooth_mesh_od_srv`
的
node
可以
被
solicited
advertise
connectable
的
advertising
events
而
不
需要
启用
Private
GATT
Proxy
state。
要
solicit
node
legacy
device
可以
通过
调用
:func:`bt_mesh_proxy_solicit`
function

Solicitation
PDU。
要
启用
这
个
feature

必须
带
:kconfig:option:`CONFIG_BT_MESH_PROXY_SOLICITATION`
option

compiled。

Solicitation
PDUs
是
non
mesh、
non
connectable、
undirected
的
advertising
messages
包含
Proxy
Solicitation
UUID
用
legacy
device
想要
connect
到
的
subnet
的
network
key
encrypted。
PDU
包含
legacy
device
的
source
address
和
一
个
sequence
number。
Sequence
number
由
legacy
device
maintain
每
个
新
的
Solicitation
PDU
