Retention
System
################

Retention
system
provide
一
个
API
它
allow
applications
从
memory
areas
或
devices
read
和
write
data
它们
在
device
被
powered
时
retain
data。
这
allow
在
不同
的
applications
之间
或
在
single
application
内
share
information
而
在
device
reboot
时
不
lose
state
information。
Stored
的
data
不
应该
在
power
failure
（或
某些
devices
上
某些
low
power
modes
期间）
时
persist
也
不
应该
被
stored
到
non
volatile
的
storage
like
:ref:`flash_api`、
:ref:`eeprom_api`、
或
battery
backed
的
RAM。

Retention
system
build
在
retained
data
driver
上面
并
向
它
add
additional
的
software
level
的
features
用于
ensure
data
的
validity。
Optionally
一
个
magic
header
可以
被
used
用于
check
retained
data
memory
section
的
front
contain
这
个
specific
的
value
且
stored
data
的
optional
的
checksum
（1、
2、
或
4
bytes
in
size）
可以
被
appended
到
data
的
end。
Additionally
retention
system
API
allow
retained
data
sections
被
partitioned
成
multiple
distinct
的
areas。
例如
一
个
64
byte
的
retained
data
area
可以
被
split
up
成
4
bytes
用于
boot
mode、
16
bytes
用于
timestamp、
44
bytes
用于
last
log
message。
所有
这些
sections
可以
independently
被
accessed
或
updated。
Prefix
和
checksum
可以
per
instance
用
devicetree
set。
