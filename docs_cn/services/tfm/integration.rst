Trusted
Firmware
M

##############################

Trusted
Firmware
M
（TF
M）

关于
TF
M
和
Zephyr
RTOS
之间

的
information。
Use
这
些
information
help
understand
如何
将
TF
M
与
Zephyr
integrate
用于
Cortex
M
platforms
并
在
Zephyr
applications
中

use
of
它
的
secure
run
time
services。

Board
Definitions
*****************

如果
:kconfig:option:`CONFIG_BUILD_WITH_TFM`
flag
被
set
到
``y``
TF
M
将
为
secure
的
processing
environment
被
built
along
with
Zephyr。

Generally
这
个
value
不
应该
在
application
level
被
set
however
且
TF
M
所需
的
所有
config
flags
应该
在
带
``_ns``
suffix
的
board
variant
中
被
set。

这
个
board
variant
必须
define
appropriate
的
flash、
SRAM
和
peripheral
configuration
它
take
into
account
secure
的
processing
environment
中
的
initialisation
process。
:kconfig:option:`CONFIG_TFM_BOARD`
也
必须
通过
`modules/trusted-firmware-m/Kconfig.tfm
<https://github.com/zephyrproject-rtos/zephyr/blob/main/modules/trusted-firmware-m/Kconfig.tfm>`__
被
set
到
TF
M
对该
target
expected
的
board
name
使
它
know
为
secure
的
processing
environment
build
哪个
target。

Example:
``mps2/an521/cpu0/ns``
===============================

``mps2/an521/cpu0``
board
target
是
一
个
dual
core
的
Arm
Cortex
M33
evaluation
board
它
generate
一
个
secure
的
Zephyr
binary。

Optional
的
``mps2/an521/cpu0/ns``
board
target
however
set
以下
additional
的
kconfig
flags
它们
indicate
Zephyr
应该
被
built
作为
一
个
non
secure
的
image
与
TF
M
linked
作为
external
的
project
且
optionally
secure
的
bootloader：

*
:kconfig:option:`CONFIG_TRUSTED_EXECUTION_NONSECURE`
``y``
*
:kconfig:option:`CONFIG_ARM_TRUSTZONE_M`
``y``
