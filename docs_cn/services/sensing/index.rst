Overview
********

Sensing
Subsystem
是
OS
user
space
service
layer
中
的
一
个
high
level
的
sensor
framework。
它
是
一
个
focused
于
sensor
fusion、
client
arbitration、
sampling、
timing、
scheduling
和
sensor
based
的
power
management
的
framework。

Sensing
Subsystem
中
的
Key
concepts
包括
physical
sensor
和
virtual
sensor
objects
以及
在
sensor
object
relationships
上面
的
一
个
scheduling
framework。
Physical
sensors
不
depend
于
任何
其他
sensor
objects
用于
input
并
将
directly
与
existing
的
zephyr
sensor
device
drivers
interact。
Virtual
sensors
rely
于
其他
sensor
objects
（physical
或
virtual）
作为
report
inputs。

Sensing
subsystem
rely
于
Zephyr
sensor
device
APIs
（existing
的
version
或
future
中
update）
用于
leverage
Zephyr
的
large
的
sensor
device
drivers
library
（100+）。

Use
sensing
subsystem
是
optional
的。
只
需要
access
simple
的
sensors
devices
的
applications
可以
直接
use
Zephyr
:ref:`sensor`
API。

因为
sensing
subsystem
与
device
driver
layer
或
kernel
space
separated
且
可以
在
user
space
中
support
各种
customizations
和
sensor
algorithms
用
virtual
sensor
concepts。
Existing
的
sensor
device
driver
可以
focus
于
low
layer
的
device
side
works
可以
保持
simple
as
much
as
possible
只
provide
device
HW
abstraction
和
operations
等。
这
对
system
stability
very
good。

Sensing
subsystem
与
任何
sensor
expose/transfer
protocols
decoupled
目标是
support
各种
up
layer
的
frameworks
和
Applications
带
不同
的
sensor
expose/transfer
protocols
such
as
`CHRE
<https://github.com/zephyrproject-rtos/chre>`_、
HID
sensors
Applications、
