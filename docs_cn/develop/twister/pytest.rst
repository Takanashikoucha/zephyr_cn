与
pytest
test
framework
集成
######################################

*请
注意
twister
与
pytest
的
集成
仍
是
work
in
progress。
不
是
每个
platform
类型
都
在
pytest
中
支持
（还
没有）。
如果
你
发现
集成
的
任何
问题
或
有
改进
的
想法，
请
让
我们
知道
并
打开
一
个
GitHub
issue/enhancement。*

Introduction
************

Pytest
是
一
个
python
framework
它
*"makes
it
easy
to
write
small,
readable
tests,
and
can
scale
to
support
complex
functional
testing
for
applications
and
libraries"*
（`<https://docs.pytest.org/en/7.3.x/>`_）。
Python
以
其
免费
库
和
用于
scripting
的
易用性
著称。
此外，
pytest
利用
plugins
和
fixtures
的
概念，
增加
其
可扩展性
和
可
重用性。
一
个
pytest
plugin
``pytest-twister-harness``
被
引入
提供
pytest
和
twister
之间
的
集成，
允许
Zephyr
的
社区
利用
pytest
功能
同时
保持
twister
作为
主
framework。

与
twister
集成
************************

默认
情况
下，
不
需要
做
任何
事情
来
在
twister
中
启用
pytest
支持。
plugin
作为
Zephyr
树
的
部分
开发。
要
启用
无
安装
操作，
twister
首先
用
指向
这
个
plugin
的
路径
扩展
``PYTHONPATH``，
然后
在
pytest
调用
期间，
它
向
命令
追加
``-p
twister_harness.plugin``
参数。
如果
一
方
偏好
使用
已
安装
的
plugin
版本，
他们
必须
向
twister
的
调用
添加
``--allow-installed-plugin``
标志。

基于
Pytest
的
test
suites
与
其他
twister
测试
同样
被
发现，
即
通过
tests.yaml
文件
的
存在。
内部，
一
个
keyword
``harness``
告诉
twister
如何
处理
给定
的
test。
在
``harness:
pytest``
的
情况
下，
twister
workflow
的
大多数
（test
suites
发现、
并行化、
构建
和
报告）
与
其他
harnesses
保持
相同。
变化
发生
在
执行
步骤
期间。

的
图
呈现
集成
的
简化
概览。
