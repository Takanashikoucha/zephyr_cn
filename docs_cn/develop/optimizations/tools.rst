工具

的

工具

你
用
不同
的
构建
系统
targets
分析
:ref:`footprint_tools`
和
:ref:`data_structure_tools`。
也

:ref:`HTML
dashboard
<dashboard>`
用于

和

更
动态

.. _footprint_tools:

Footprint
和
内存
使用
**************************

构建
系统
提供
3
个
targets
查看
和
分析
生成
的
images
中
的
RAM、
ROM
和
stack
使用。
工具
在
最终
image
上
运行
并
给出
关于
RAM
和
ROM
中
使用
的
symbols
和
代码
大小
的
信息。
此外，
用
编译器
可用
的
功能，
我们
也
可以
生成
worst-case
stack
使用
分析。

本
节
提到
的
一些
工具
基于
symbols
的
物理
组织
组织
它们
的
输出。
由于
一些
symbols
可能
在
项目
的
树
结构
之外，
或
可能
缺乏
显示
它们
按
名称
所需
的
元数据，
以下
顶层
容器
用
来
分组
这样
的
symbols：

* Hidden
  -
  RAM
  和
  ROM
  报告
  列出
  所有
  没有
  匹配
  mapped
  文件
  的
  处理
  symbols
  在
  Hidden
  类别
  中。

  这
  意味着
  列出
  的
  symbol
  的
  文件
  未
  添加
  到
  元数据
  文件，
  是
  空
  的，
  或
  未
  定义。
  工具
  无法
  获取
  给定
  symbol
  的
  函数
  名称
  也
  无法
  识别
  它
  来自
  哪里。

* No
  paths
  -
  RAM
  和
  ROM
  报告
  列出
  所有
  带
  相对
  路径
  的
  处理
  symbols
  在
  No
  paths
  类别
  中。

  这
  意味着
  列出
  的
  symbols
  不能
  被
  放置
  在
  报告
  的
  树
  结构
  中
  一
  个
  特定
  文件
  下
  的
  绝对
  路径
  处。
  工具
  能
  获取
  函数
  名称，
  但
  无法
  识别
  它
  来自
  哪里。
