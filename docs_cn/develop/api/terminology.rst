.. _api_terms:

API
术语
###############

以下
术语
可以
作为
简写
API
标签
使用，
用于
指示
允许
的
调用
上下文
（线程、
ISR、
pre-kernel）、
调用
对
当前
线程
状态
的
影响，
以及
其他
行为
特征。

:ref:`api_term_reschedule`
   如果
   执行
   函数
   到达
   重新
   调度
   点
:ref:`api_term_sleep`
   如果
   执行
   函数
   可以
   导致
   调用
   线程
   睡眠
:ref:`api_term_no-wait`
   如果
   函数
   的
   参数
   可以
   防止
   调用
   线程
   尝试
   睡眠
:ref:`api_term_isr-ok`
   如果
   函数
   可以
   安全
   调用
   并
   将
   有
   其
   指定
   效果，
   无论
   从
   中断
   还是
   线程
   上下文
   调用
:ref:`api_term_pre-kernel-ok`
   如果
   函数
   可以
   在
   内核
   完全
   初始化
   前
   安全
   调用
   并
   从
   那个
   上下文
   调用
   时
   将
   有
   其
   指定
   效果。
:ref:`api_term_async`
   如果
   函数
   可能
   在
   它
   初始化
   的
   操作
   完成
   前
   返回
   （即
   函数
   返回
   和
   操作
   完成
   是
   异步
   的）
:ref:`api_term_supervisor`
   如果
   调用
   线程
   必须
   有
   监督
   权限
   才能
   执行
   函数

每个
属性
的
行为
影响
的
细节
在
以下
章节
中。

.. _api_term_reschedule:

reschedule
==========

reschedule
属性
用
于
可以
在其
执行
中
到达
:ref:`重新
调度
点 <scheduling_v2>`
的
函数。

细节
-------

这个
属性
的
意义
是
当
线程
调用
重新
调度
函数
时，
该
线程
可能
被
挂起
作为
更高
优先级
线程
变
就绪
的
结果。
挂起
是否
实际
发生
取决于
与
重新
调度
点
关联
的
操作
和
调用
线程
与
就绪
队列
队头
的
相对
优先级。

注意
在
时间
片
的
情况
下，
或
从
中断
执行
的
重新
调度
点，
任何
线程
可能
在
任何
函数
中
被
挂起。

不
是
**reschedule**
的
函数
可以
从
线程
或
中断
上下文
调用。

是
**reschedule**
的
函数
可以
从
线程
上下文
调用。

是
**reschedule**
但
不
是
**sleep**
的
函数
可以
从
中断
上下文
调用。

.. _api_term_sleep:

sleep
=====

sleep
属性
用
于
可以
导致
调用
线程
:ref:`睡眠 <scheduling_v2>`
的
函数。

解释
-----------

这个
属性
在
特别
考虑
只
使用
非
可
抢占
线程
的
应用
时
相关，
因为
除非
该
线程
显式
调用
了
导致
它
睡眠
的
操作，
内核
不
会
在
重新
调度
点
替换
运行
的
协作
线程。

这个
属性
不
意味
函数
将
无条件
睡眠，
但
意味
操作
可能
需要
一个
调用
线程，
它
在
能
完成
其
操作
前
必须
挂起、
等待
或
调用
:c:func:`k_yield`。
这个
行为
可能
被
**no-wait**
调解。

是
**sleep**
的
函数
隐式
是
**reschedule**。

是
**sleep**
的
函数
可以
从
线程
上下文
调用。

是
**sleep**
的
函数
可以
从
中断
和
pre-kernel
上下文
调用
当
且
仅当
在
**no-wait**
模式
下
调用。

.. _api_term_no-wait:

no-wait
=======

no-wait
属性
用
于
也
是
**sleep**
的
函数
以
指示
函数
的
参数
可以
强制
一个
不会
导致
调用
线程
睡眠
的
执行
路径。

解释
-----------

no-wait
函数
的
典范
情况
是
一个
接受
超时
的
函数，
可以
向
它
传递
:c:macro:`K_NO_WAIT`。
这个
特殊
超时
值
的
语义
是
执行
函数
的
操作
只要
它
可以
立即
完成，
如果
不
能
就
返回
错误
代码
而非
睡眠。

正是
no-wait
功能
的
使用
使
像
:c:func:`k_sem_take`
这样
的
函数
可以
从
ISR
调用，
因为
不
允许
在
中断
上下文
中
睡眠。

有
no-wait
路径
的
函数
不
意味
走
那个
路径
保证
函数
是
同步
的。

有
这个
属性
的
函数
可以
从
中断
和
pre-kernel
上下文
调用
只
在
参数
选择
no-wait
路径
时。

.. _api_term_isr-ok:

isr-ok
======

isr-ok
属性
用
于
函数
以
指示
它
无论
从
中断
还是
线程
上下文
调用
都
工作。

解释
-----------

任何
不
是
**sleep**
的
函数
固有
是
**isr-ok**。
是
**sleep**
的
函数
是
**isr-ok**
如果
实现
确保
即使
从
中断
上下文
调用
也
实现
记录
的
行为。
这
可以
通过
让
实现
检测
调用
上下文
并
将
会
睡眠
的
操作
转移
到
线程
来
实现，
或
通过
记录
当
从
非
线程
上下文
调用
时
函数
将
返回
特定
错误
（通常
``-EWOULDBLOCK``）。

注意
是
**no-wait**
的
函数
只
在
选择
no-wait
路径
时
从
中断
上下文
调用
安全。
**isr-ok**
函数
不
需要
提供
no-wait
路径。

.. _api_term_pre-kernel-ok:

pre-kernel-ok
=============

pre-kernel-ok
属性
用
于
函数
以
指示
它
即使
在
内核
主
线程
启动
前
调用
也
按
记录
工作。

解释
-----------

这个
属性
在
功能
上
类似
于
**isr-ok**，
但
旨在
用于
任何
预期
在
:c:macro:`DEVICE_DEFINE()`
或
:c:macro:`SYS_INIT()`
调用
中
被
调用
的
API，
这些
调用
可能
用
``PRE_KERNEL_1``
或
``PRE_KERNEL_2``
初始化
级别
调用。

通常
是
**pre-kernel-ok**
的
函数
在
确定
它
是否
能
满足
其
需要
的
行为
时
检查
:c:func:`k_is_pre_kernel`。
在
许多
情况
下
它
也
会
检查
:c:func:`k_is_in_isr`
使
它
也
是
**isr-ok**。

.. _api_term_async:

async
=====

函数
是
**async**
（即
异步）
如果
它
可能
在
它
启动
的
操作
完成
前
返回。
异步
函数
通常
提供
一个
机制
报告
操作
完成，
例如
回调
或
事件。

不
是
异步
的
函数
是
同步
的，
即
操作
在
函数
返回
时
始终
完成。
由于
大多数
函数
是
同步
的，
这个
行为
没有
一个
单独
的
属性
来
标识
它。

解释
-----------

注意
**async**
与
上下文
切换
正交。
某些
API
可能
通过
回调
提供
完成
信息，
但
可能
在
等待
启动
操作
所需
的
资源
时
挂起；
一个
示例
是
:c:func:`spi_transceive_signal`。

如果
函数
同时
是
**no-wait**
和
**async**，
那么
选择
no-wait
路径
只
保证
函数
不
会
睡眠。
它
不
影响
操作
是否
在
函数
返回
前
完成。

.. _api_term_supervisor:

supervisor
==========

supervisor
属性
只
在
用户
模式
应用
中
相关，
并
指示
函数
不
能
从
用户
模式
调用。
