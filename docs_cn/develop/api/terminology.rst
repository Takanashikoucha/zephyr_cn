.. _api_terms:

API 术语
###############

以下术语可用作简写的 API 标签，用于指示允许的调用上下文（线程、中断服务程序、内核启动前）、
调用对当前线程状态的影响，以及其他行为特征。

:ref:`api_term_reschedule`
   如果执行该函数会到达重新调度点
:ref:`api_term_sleep`
   如果执行该函数可能导致调用线程进入睡眠
:ref:`api_term_no-wait`
   如果函数的某个参数可以防止调用线程尝试睡眠
:ref:`api_term_isr-ok`
   如果无论从中断上下文还是线程上下文调用，该函数都能安全执行并产生其指定的效果
:ref:`api_term_pre-kernel-ok`
   如果该函数可以在内核完全初始化之前安全调用，并且从该上下文调用时能产生其指定的效果
:ref:`api_term_async`
   如果该函数可能在其发起的操作完成之前返回（即函数返回与操作完成是异步的）
:ref:`api_term_supervisor`
   如果调用线程必须具有监督者权限才能执行该函数

各属性对行为影响的详细说明见以下各节。

.. _api_term_reschedule:

重新调度
==========

重新调度属性用于那些在执行过程中可能到达 :ref:`重新调度点 <scheduling_v2>` 的函数。

细节
-------

该属性的意义在于：当线程调用一个具有重新调度属性的函数时，
该线程有可能因为更高优先级的线程变为就绪状态而被挂起。
挂起是否实际发生，取决于与重新调度点相关联的操作，
以及调用线程与就绪队列队头线程的相对优先级。

需要注意的是，在时间片轮转的情况下，或从中断中执行的重新调度点，任何线程都可能在任何函数中被挂起。

不具有 **重新调度** 属性的函数可以从线程上下文或中断上下文调用。

具有 **重新调度** 属性的函数可以从线程上下文调用。

具有 **重新调度** 属性但不具有 **睡眠** 属性的函数可以从中断上下文调用。

.. _api_term_sleep:

睡眠
=====

睡眠属性用于那些可能导致调用线程 :ref:`睡眠 <scheduling_v2>` 的函数。

说明
-----------

该属性在考虑仅使用非可抢占线程的应用程序时尤为重要，
因为除非该线程显式调用了某个使其睡眠的操作，
否则内核不会在重新调度点替换正在运行的纯协作式线程。

该属性并不意味着函数会无条件地睡眠，
而是表示该操作可能需要调用线程先挂起、等待
或调用 :c:func:`k_yield` 之后才能完成其操作。
这种行为可能通过 **不等待** 属性来调节。

具有 **睡眠** 属性的函数隐式具有 **重新调度** 属性。

具有 **睡眠** 属性的函数可以从线程上下文调用。

具有 **睡眠** 属性的函数可以从中断上下文和内核启动前上下文调用，当且仅当以 **不等待** 模式调用时。

.. _api_term_no-wait:

不等待
=======

不等待属性用于同时具有 **睡眠** 属性的函数，
用于表示该函数的某个参数可以强制走一条
不会导致调用线程睡眠的执行路径。

说明
-----------

不等待函数的典型例子是一个接受超时参数的函数，
可以向该函数传递 :c:macro:`K_NO_WAIT`。
这个特殊超时值的语义是：只要操作能够立即完成就执行该操作，
如果不能立即完成则返回一个错误码而不是睡眠。

正是由于不等待特性的使用，使得像 :c:func:`k_sem_take` 这样的函数可以从中断服务程序中调用，因为中断上下文中不允许睡眠。

具有不等待路径的函数并不意味着走该路径就能保证函数是同步的。

具有该属性的函数仅当参数选择了不等待路径时，才可以从中断上下文和内核启动前上下文调用。

.. _api_term_isr-ok:

中断安全
======

中断安全属性用于表示某个函数无论从中断上下文还是线程上下文调用都能正常工作。

说明
-----------

任何不具有 **睡眠** 属性的函数天然就是 **中断安全** 的。
具有 **睡眠** 属性的函数，如果其实现确保即使从中断上下文调用
也能实现文档中描述的行为，那么它也是 **中断安全** 的。
这可以通过让实现检测调用上下文并将原本会导致睡眠的操作转移到线程中执行来实现，
也可以通过文档说明当从非线程上下文调用时函数将返回特定错误（通常是 ``-EWOULDBLOCK``）来实现。

需要注意的是，具有 **不等待** 属性的函数
仅在选择不等待路径时才可以安全地从中断上下文调用。
**中断安全** 函数则不需要提供不等待路径。

.. _api_term_pre-kernel-ok:

内核启动前安全
=============

内核启动前安全属性用于表示某个函数即使在内核主线程启动之前调用，也能按照文档描述的方式正常工作。

说明
-----------

该属性在功能上类似于 **中断安全**，
但专门用于那些预期在 :c:macro:`DEVICE_DEFINE()` 或 :c:macro:`SYS_INIT()` 调用中被调用的 API，
而这些调用可能以 ``PRE_KERNEL_1`` 或 ``PRE_KERNEL_2`` 初始化级别被调用。

通常，具有 **内核启动前安全** 属性的函数
在判断自己能否满足所需行为时会检查 :c:func:`k_is_pre_kernel`。
在许多情况下，它还会检查 :c:func:`k_is_in_isr`，
从而使其同时也是 **中断安全** 的。

.. _api_term_async:

异步
=====

如果函数可能在其发起的操作完成之前返回，
则该函数是 **异步** 的。
异步函数通常会提供一种机制来报告操作完成，例如回调或事件。

不是异步的函数就是同步的，
即操作在函数返回时一定已经完成。
由于大多数函数都是同步的，因此该行为没有单独的属性来标识。

说明
-----------

需要注意的是，**异步** 与上下文切换是正交的。
某些 API 可能通过回调提供完成信息，
但在等待启动操作所需资源的过程中可能会挂起；
例如 :c:func:`spi_transceive_signal`。

如果一个函数同时具有 **不等待** 和 **异步** 属性，
那么选择不等待路径仅保证函数不会睡眠。
它并不影响操作是否在函数返回之前完成。

.. _api_term_supervisor:

监督者
==========

监督者属性仅对用户模式应用程序有意义，用于表示该函数不能从用户模式调用。
