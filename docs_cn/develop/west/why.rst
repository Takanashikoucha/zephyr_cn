History
and
Motivation
######################

West
被
添加
到
Zephyr
项目
以
满足
两
个
根本
要求：

* 与
  多
  个
  Git
  仓库
  工作
  的
  能力
* 提供
  可
  扩展
  和
  用户
  友好
  的
  命令行
  接口
  的
  能力
  用于
  基本
  Zephyr
  工作流

在
west
的
开发
期间，
一
套
:ref:`west-design-constraints`
被
识别
出
以
避免
这
类
工具
的
常见
陷阱。

Requirements
************

虽然
将
Zephyr
代码库
拆分
成
多
个
仓库
的
动机
在
本
页
范围
之外，
根本
要求
连同
不
使用
现有
工具
而
是
开发
新
的
选择
的
清晰
论证
确实
属于
这里。

基本
要求
是：

* **R1**：
  将
  外部
  维护
  的
  代码
  保留
  在
  主
  zephyr
  仓库
  之外
  单独
  维护
  的
  仓库
  中，
  而
  不
  要求
  用户
  手动
  clone
  每个
  外部
  仓库
* **R2**：
  提供
  一
  个
  Zephyr
  用户
  和
  发行版
  都
  可以
  利用
  来
  受益
  和
  扩展
  的
  工具
* **R3**：
  允许
  用户
  和
  下游
  发行版
  覆盖
  或
  移除
  仓库
  而
  不
  需要
  对
  zephyr
  仓库
  做
  更改
* **R4**：
  支持
  连续
  跟踪
  和
  commit
  基于
  （可
  bisect）
  的
  project
  更新
