.. _coverage:

生成
覆盖率
报告
###########################

在
Zephyr
中，
你
可以
生成
代码
覆盖率
报告
分析
代码
的
哪些
部分
被
给定
的
测试
或
应用
覆盖。

你
可以
用
两种
方式
做
到
这：

* 在
  真实
  嵌入式
  目标
  或
  QEMU
  中，
  用
  Zephyr
  的
  gcov
  集成
* 直接
  在
  你
  的
  主机
  计算机
  上，
  通过
  编译
  你
  的
  应用
  目标
  为
  POSIX
  架构

嵌入式
设备
或
QEMU
中
的
测试
覆盖率
报告
*************************************************

概览
========
`GCC
GCOV
<gcov_>`_
是
一
个
测试
覆盖率
程序，
与
GCC
编译器
一起
使用
分析
和
创建
测试
覆盖率
报告
用于
你
的
程序，
帮助
你
创建
更
高效、
更
快
运行
的
代码
并
发现
未
测试
的
代码
路径

在
Zephyr
中，
gcov
在
你
的
应用
运行
时
在
RAM
中
收集
覆盖率
剖析
数据
（而
非
到
文件
系统）。
gcov
收集
和
报告
的
支持
受
可用
RAM
大小
限制，
因此
目前
只
为
嵌入式
目标
的
QEMU
模拟
启用。

细节
=======
启用
这
个
功能
有
2
个
部分。
第一
个
是
为
设备
启用
覆盖率，
第二
个
是
在
测试
应用
中
启用。
如
前面
所
解释
的，
用
gcov
的
代码
覆盖率
是
可用
RAM
的
函数。
因此
确保
设备
在
启用
覆盖率
时
有
足够
的
RAM。
例如
像
frdm_k64f
这样
的
小
设备
可以
运行
简单
的
测试
应用
但
消费
更多
RAM
的
更
复杂
测试
用例
在
启用
覆盖率
时
会
崩溃。

要
为
设备
启用
覆盖率，
在
Kconfig.board
文件
中
选择
:kconfig:option:`CONFIG_HAS_COVERAGE_SUPPORT`。

要
报告
特定
测试
应用
的
覆盖率
设置
:kconfig:option:`CONFIG_COVERAGE`。

代码
