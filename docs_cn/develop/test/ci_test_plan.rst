CI
测试
计划
选择器
（test_plan_v2）
#####################################

CI
测试
计划
选择器
是
一
个
模块化
的
Python
脚本
位于
``scripts/ci/test_plan_v2.py``。
其
目的
是
分析
Pull
Request
中
更改
的
文件
集
并
发出
定向
的
twister
测试
计划
——
只
执行
可能
受
更改
影响
的
测试
同时
避免
每
个
commit
上
的
完整
树
范围
运行。

脚本
写入
两
个
产物：

* ``testplan.json``
  ——
  通过
  ``twister
  --load-tests``
  传递
  给
  twister。
* ``.testplan``
  ——
  一
  个
  纯
  ``KEY=value``
  环境
  文件
  被
  CI
  编排
  脚本
  消费，
  包含
  ``TWISTER_TESTS``、
  ``TWISTER_NODES``
  和
  ``TWISTER_FULL``。

架构
************

选择器
围绕
一
个
*策略
管道*
构建。
每个
策略
是
一
个
独立
的
分析器
它：

1. 接收
   更改
   文件
   列表
   （或
   尚未
   被
   之前
   策略
   消费
   的
   子集）。
2. 根据
   其
   自己
   的
   逻辑
   检查
   那些
   文件。
3. 返回
   :class:`TwisterCall`
   描述符
   列表
   和
   它
   *已
   处理*
   的
   文件
   集。

:class:`Orchestrator`
驱动
管道，
合并
所有
结果
到
:class:`PlanAccumulator`，
去重
测试
套件
并
写入
输出
文件。

策略
排序
*****************

策略
按
固定
顺序
运行
反映
两
个
原则：

**特定性
优先
于
通用性。**
最
精确
的
策略
先
运行。
位于
``tests/kernel/sched/``
中
的
文件
在
catch-all
:class:`MaintainerAreaStrategy`
可以
添加
整个
Kernel
区域
扫描
之前
被
:class:`DirectTestStrategy`
（精确
运行
那些
测试）
确定
性
处理。

**先
消费
后
添加。**
消费
策略
在
添加
策略
之前
运行。
一
旦
消费
策略
声明
一
个
文件，
下游
策略
永远
不
会
看到
它。
这
防止
对
board
文件
的
更改
同时
触发
驱动
兼容
扫描
和
同一
路径
的
Kconfig
扫描。

顺序
